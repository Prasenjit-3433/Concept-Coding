# LC 583. Delete Operation for Two Strings

*(Continuing Pattern 7 — another reduction to LC 1143, this time using the LCS as a "keep intact" anchor rather than a palindrome trick)*

---

# Stage 1: Identification

**Step 1 — Which topic?**

You're given two strings, `word1` and `word2`. The only operation allowed is **deleting a character** from either string (any character, any position, any number of times). You need the **minimum total number of deletions** to make the two strings identical.

```
word1 = "sea"
word2 = "eat"

Delete 's' from word1  → "ea"
Delete 't' from word2  → "ea"

Total deletions = 2, and both strings now equal "ea"
```

**Step 2 — Which pattern?**

Two strings, comparing them character by character, looking for a shared structure — this is **Pattern 7: LCS**, and unlike the last two problems, this one hands you two strings directly, exactly like LC 1143. No reversal trick needed here.

**Step 3 — Which key concept?**

**"What can I avoid touching?"** — this is the guiding question Striver poses, and it's a genuinely useful general habit for *any* problem involving insertions/deletions/edits: minimizing operations is the same as maximizing what you *don't* have to change.

If only deletions are allowed, the only way two strings can end up equal is if they both get reduced down to some common "core" — and whatever that core is, every character *not* in it must be deleted from wherever it sits. To minimize total deletions, you want to keep the **largest possible core** intact, since a bigger core means fewer characters left over to delete on both sides.

That "largest possible shared core, order preserved" is exactly the definition of the **Longest Common Subsequence** — you already own this solver completely from LC 1143. This problem is once again a reduction, not a new recurrence.

---

# Stage 2: Intuition Building

### Why "Keep the Common Part, Delete Everything Else" Is Optimal

Take Striver's example: `word1 = "abcd"`, `word2 = "anc"`.

The only operations available are deletions — you cannot insert, and you cannot swap or replace a character in place. So the only way to make the two strings equal is to strip characters away from each side until what remains is identical on both sides.

Ask: what is the biggest "identical remainder" you could possibly land on? It has to be a subsequence of `word1` (since you're only removing characters, never reordering them), and it also has to be a subsequence of `word2` for the same reason. A sequence of characters that is simultaneously a subsequence of both strings is — by definition — a **common subsequence**. And since you want to delete as *few* characters as possible, you want that shared remainder to be as *large* as possible — which means you want the **longest** common subsequence.

```
word1 = "abcd"
word2 = "anc"

Longest common subsequence: "ac"   (length 2)

Keep "ac" untouched in BOTH strings:
  word1:  a b c d   →  keep a, c → delete b, d   (2 deletions)
  word2:  a n c     →  keep a, c → delete n       (1 deletion)

Total deletions = 2 + 1 = 3
```

Every character in `word1` that is *not* part of this shared `"ac"` core must be deleted — there is no other option, since insertions aren't allowed and the two strings must end up exactly equal. The same logic applies to `word2`. So the total number of deletions is completely determined once you know the length of the longest common subsequence.

### Turning This Into a Formula

Let `n = word1.length()`, `m = word2.length()`, and `L = LCS(word1, word2)`.

```
Characters kept in word1  = L        →  characters deleted from word1 = n - L
Characters kept in word2  = L        →  characters deleted from word2 = m - L

Total minimum deletions = (n - L) + (m - L) = n + m - 2L
```

Verify against the example: `n = 4`, `m = 3`, `L = 2` → `4 + 3 - 2(2) = 7 - 4 = 3` ✓, matching the hand-count above.

### Why the LCS Is Guaranteed to Be Reachable by Deletions Alone

It's worth being explicit about why this works cleanly. A subsequence, by definition, is what remains when you delete zero or more characters from a string while keeping the rest in their original relative order. So if `"ac"` is a common subsequence of both `word1` and `word2`, that automatically means there exists *some* sequence of deletions on `word1` that leaves exactly `"ac"` behind, and *some* sequence of deletions on `word2` that leaves exactly `"ac"` behind. Nothing extra needs to be proven or constructed — the definition of "common subsequence" already guarantees deletions alone can produce it on both sides.

### Why You Cannot Do Better Than the LCS

Suppose, for contradiction, that you found some way to make the two strings equal using fewer total deletions than `n + m - 2L`. Whatever the final equal string is, it must be reachable from `word1` by deletions only, and also reachable from `word2` by deletions only — meaning it is, by definition, a common subsequence of `word1` and `word2`. But `L` is already the *longest possible* common subsequence — so this hypothetical final string cannot be any longer than `L`. Keeping *fewer* than `L` characters common can only ever mean deleting *more* characters overall, never fewer. So `n + m - 2L` is not just *an* achievable answer — it's the *minimum* achievable one.

### The Reduction, Stated Plainly

```
LC 583 — Delete Operation for Two Strings
    ↓  n + m - 2 × LCS(word1, word2)
LC 1143 — Longest Common Subsequence
```

One layer of reduction, one arithmetic formula on top of a solver you already have. No new recurrence, no new base case — the entire "new" content of this problem is the formula `n + m - 2L` and the reasoning behind it.

# Stage 3: Coding

## Approach — Tabulation (direct reuse of LC 1143's solver)

```java
class Solution {
    public int minDistance(String word1, String word2) {
        int n = word1.length();
        int m = word2.length();

        // Step 1: run the EXACT LC 1143 LCS tabulation, unchanged
        // dp[i][j] = LCS length of word1[0..i-1] and word2[0..j-1]
        int[][] dp = new int[n + 1][m + 1];

        for (int i = 1; i <= n; i++) {
            for (int j = 1; j <= m; j++) {
                if (word1.charAt(i - 1) == word2.charAt(j - 1)) {
                    dp[i][j] = 1 + dp[i - 1][j - 1];
                } else {
                    dp[i][j] = Math.max(dp[i - 1][j], dp[i][j - 1]);
                }
            }
        }

        int lcs = dp[n][m];

        // Step 2: the ONLY new line in this entire problem.
        // WHY n + m - 2*lcs: every character NOT part of the shared
        // core (of length lcs) in EITHER string must be deleted —
        // (n - lcs) deletions from word1, (m - lcs) deletions from word2
        return n + m - 2 * lcs;
    }
}
```

### Full Cell-by-Cell DP Table Trace

`word1 = "sea"` (n = 3), `word2 = "eat"` (m = 3) — the actual LeetCode example.

```
                  j=0    j=1(e)  j=2(a)  j=3(t)
i=0           [   0   ,   0   ,   0   ,   0   ]
i=1(s)        [   0   ,   0   ,   0   ,   0   ]
i=2(e)        [   0   ,   1   ,   1   ,   1   ]
i=3(a)        [   0   ,   1   ,   2   ,   2   ]
```

Walking through the key cells:

- `dp[2][1]`: `word1[1]='e'`, `word2[0]='e'` → match → `1 + dp[1][0] = 1 + 0 = 1`
- `dp[3][2]`: `word1[2]='a'`, `word2[1]='a'` → match → `1 + dp[2][1] = 1 + 1 = 2`
- `dp[3][3]`: `word1[2]='a'`, `word2[2]='t'` → no match → `max(dp[2][3]=1, dp[3][2]=2) = 2`

**`dp[3][3] = 2`** → `LCS("sea", "eat") = 2` (the shared core is `"ea"`).

**Final answer = `n + m - 2·lcs = 3 + 3 - 2(2) = 6 - 4 = 2`** ✓ — matches the expected result exactly (delete `'s'` from `"sea"`, delete `'t'` from `"eat"`, both become `"ea"`).

## Approach — Space Optimization

Identical collapse to every other problem in this pattern — row `i` only needs row `i-1` and the current row's earlier entries.

```java
class Solution {
    public int minDistance(String word1, String word2) {
        int n = word1.length();
        int m = word2.length();

        int[] prev = new int[m + 1];

        for (int i = 1; i <= n; i++) {
            int[] curr = new int[m + 1];

            for (int j = 1; j <= m; j++) {
                if (word1.charAt(i - 1) == word2.charAt(j - 1)) {
                    curr[j] = 1 + prev[j - 1];
                } else {
                    curr[j] = Math.max(prev[j], curr[j - 1]);
                }
            }

            prev = curr;
        }

        int lcs = prev[m];
        return n + m - 2 * lcs;
    }
}
```

---

## Complexity Analysis

**Time Complexity — O(n × m):**

The LCS tabulation is the entire cost — two nested loops of size `n` and `m`. The final formula is a single `O(1)` arithmetic step. Total: **O(n × m)**, identical to LC 1143 itself, since this problem adds no extra computational work beyond it.

**Space Complexity — O(m) after optimization:**

Same as every LCS-based problem so far — full tabulation is `O(n × m)`, space-optimized version collapses to two rolling arrays of size `m + 1`, giving **O(m)**.
