# LC 1312. Minimum Insertion Steps to Make String Palindrome

*(Continuing Pattern 7 — builds directly on LC 516's reduction, one more layer of reasoning on top)*

---

# Stage 1: Identification

**Step 1 — Which topic?**

You're given a string. You may **insert** any character at any position, any number of times. You need the **minimum number of insertions** required to turn the string into a palindrome.

```
s = "abcaa"

This is NOT a palindrome (reversed: "aacba" ≠ "abcaa")

Can we make it a palindrome by inserting characters?
Yes — e.g. insert "b" and "c" to get "abcaacba"... 
but we want the MINIMUM number of insertions, not just any valid one.
```

**Step 2 — Which pattern?**

Still **Pattern 7: LCS**. Once again, only *one* string is handed to you — exactly like LC 516. That should immediately make you suspicious that this problem, too, is going to reduce to something you already own, rather than needing brand-new DP machinery.

**Step 3 — Which key concept?**

**A second-layer reduction, built directly on top of LC 516.**

The key insight: whatever the minimum number of insertions turns out to be, it is going to equal:

```
minimum insertions = n - (longest palindromic subsequence of s)
```

where `n` is the length of the string. Once you see why this formula holds, the entire problem collapses to: run LC 516's solution (which itself reduces to LC 1143's LCS), then subtract from `n`. No new recurrence, no new state — this is problem reduction stacked two layers deep.

# Stage 2: Intuition Building

### Striver's Framing — Keep the Palindrome Intact, Mirror the Rest

Start by noticing something obvious: **you can always turn any string into a palindrome**, no matter how messy it is. The crude way to do it: take the whole string, reverse it, and glue the reverse onto the end.

```
s = "abcaa"
reverse(s) = "aacba"

s + reverse(s) = "abcaa" + "aacba" = "abcaaaacba"
```

This is guaranteed to be a palindrome (a string glued to its own mirror image always is), and it required exactly `n = 5` insertions (the entire reversed half was newly inserted). So `n` insertions is always *an* upper bound on the answer — but it's rarely the *minimum*.

Here's the sharper idea: if some **portion of the string is already a palindrome**, you don't need to touch it at all — you only need to fix up the characters that fall *outside* that palindromic portion. And to minimize total work, you should pick the **longest** such palindromic portion, because every character inside it is "free" (already mirrored), and every character outside it is where the cost comes from.

Take `s = "abcaa"`. The longest palindromic *subsequence* hiding inside it is `"aca"` — using the `a` at index 0, the `c` at index 2, and the `a` at index 3 (or 4). That's a palindrome of length 3, and it's the longest one you can pull out of this string. The other two characters — `b` (index 1) and one of the `a`'s (whichever wasn't used) — are **not** part of that palindromic backbone. For the *whole* string to become a palindrome, those leftover characters need a matching mirror-image partner inserted somewhere on the opposite side. Two leftover characters means two insertions.

```
Keep intact:  a . c . a       (the palindrome backbone — untouched)
Leftover:     . b . a .       (needs a mirror partner each)

Total insertions needed = leftover count = 2
```

### Your Framing — Mirror Images, Directly

Your way of seeing this is the same conclusion reached from a slightly different angle, and it's worth stating explicitly because it generalizes cleanly.

Think of the final palindrome you're building as a sequence of character *pairs*, symmetric around a center:

```
position:     0    1    2(center)   3    4
character:    a    b     c          a    a
```

For the whole string to be a palindrome, **every character needs a mirror partner** at the symmetric position — except possibly one character sitting exactly at the center (only relevant when the total length is odd).

Look at `s = "abcaa"` through this lens:

- The `a` at index 0 and the `a` at index 4 already mirror each other — a matching pair, free of charge.
- The `c` in between can sit at the very center of the final palindrome — a center character never needs a partner, so it's free too.
- That leaves `b` (index 1) and the leftover `a` (index 3) — **neither one has a mirror partner anywhere in the string**. Each of these needs a matching character inserted on the opposite side to complete its pair.

```
┌───────────────────────────────────────────────────────────────────┐
│  Every character in the final palindrome belongs to exactly one   │
│  of two groups:                                                   │
│                                                                   │
│    Group 1 — already has a mirror partner within s                │
│              (or sits at the exact center, needing no partner)    │
│              → contributes to the LONGEST PALINDROMIC SUBSEQUENCE │
│                                                                   │
│    Group 2 — has no mirror partner anywhere in s                  │
│              → needs ONE new character inserted to give it one    │
│                                                                   │
│  The count of Group 2 characters is exactly what you must insert. │
└───────────────────────────────────────────────────────────────────┘
```

### Why This Is Exactly "n minus the Longest Palindromic Subsequence"

Group 1 — the characters that already have a mirror partner (or sit at the center) — is, by definition, the **longest palindromic subsequence** of `s`. That's precisely what LC 516 computes: the longest run of characters you can pick out of `s`, in order, that already reads the same forwards and backwards.

Every character *not* included in that longest palindromic subsequence is, by definition, a Group 2 character — one with no existing mirror partner. Since the string has `n` characters total, and the longest palindromic subsequence accounts for `LPS(s)` of them, the remaining `n - LPS(s)` characters are exactly the ones needing a freshly inserted partner.

```
n = 5   (total characters in "abcaa")
LPS(s) = 3   (the palindromic backbone "aca")

Characters without a mirror partner = 5 - 3 = 2   → the "b" and the leftover "a"

Minimum insertions = n - LPS(s) = 5 - 3 = 2 ✓
```

This matches Striver's "keep the palindrome intact, copy the rest" framing exactly — the characters he copies and mirrors onto the opposite side are precisely the Group 2 characters that lack a partner. Both framings land on the identical formula; yours simply names the "why" in terms of pairing rather than in terms of copying, which makes the formula feel less like a trick and more like counting.

### Why You Never Need to Actually *Construct* the Palindrome

The problem only asks for the **count** of insertions, not the final palindrome string itself. So you never need to simulate the copying or figure out exactly where each leftover character gets mirrored to. You only need two numbers: the length of the string, and the length of its longest palindromic subsequence. Subtract, and you're done.

### The Full Reduction Chain

```
LC 1312 — Minimum Insertions to Make Palindrome
    ↓  n - LPS(s)
LC 516 — Longest Palindromic Subsequence
    ↓  LCS(s, reverse(s))
LC 1143 — Longest Common Subsequence
```

Three problems, two reductions, one underlying recurrence. This is the deepest reduction chain you've built so far in Pattern 7 — and it's a good demonstration of why recognizing a reduction is often worth more than knowing how to write a new recurrence from scratch.

# Stage 3: Coding

Since the entire problem is `n - LPS(s)`, and `LPS(s) = LCS(s, reverse(s))`, the code is just LC 516's solver with one line added at the end.

## Approach — Tabulation (direct reuse of LC 516's solver)

```java
class Solution {
    public int minInsertions(String s) {
        int n = s.length();

        // Step 1: build the reverse of s — same first step as LC 516
        String t = new StringBuilder(s).reverse().toString();

        // Step 2: run the exact LC 1143 LCS tabulation on (s, t)
        // dp[i][j] = LCS length of s[0..i-1] and t[0..j-1]
        int[][] dp = new int[n + 1][n + 1];

        for (int i = 1; i <= n; i++) {
            for (int j = 1; j <= n; j++) {
                if (s.charAt(i - 1) == t.charAt(j - 1)) {
                    dp[i][j] = 1 + dp[i - 1][j - 1];
                } else {
                    dp[i][j] = Math.max(dp[i - 1][j], dp[i][j - 1]);
                }
            }
        }

        // dp[n][n] = LCS(s, reverse(s)) = longest palindromic subsequence of s
        int lps = dp[n][n];

        // Step 3: the ONLY new line in this entire problem.
        // WHY n - lps: every character NOT part of the longest palindromic
        // backbone has no mirror partner and needs exactly one insertion
        // to gain one.
        return n - lps;
    }
}
```

### Full Cell-by-Cell DP Table Trace

`s = "abcaa"` (n = 5), `t = reverse(s) = "aacba"`

```
                j=0    j=1(a)  j=2(a)  j=3(c)  j=4(b)  j=5(a)
i=0          [   0   ,   0   ,   0   ,   0   ,   0   ,   0   ]
i=1(a)       [   0   ,   1   ,   1   ,   1   ,   1   ,   1   ]
i=2(b)       [   0   ,   1   ,   1   ,   1   ,   2   ,   2   ]
i=3(c)       [   0   ,   1   ,   1   ,   2   ,   2   ,   2   ]
i=4(a)       [   0   ,   1   ,   2   ,   2   ,   2   ,   3   ]
i=5(a)       [   0   ,   1   ,   2   ,   2   ,   2   ,   3   ]
```

A handful of cells worth checking directly:

- `dp[1][1]`: `s[0]='a'`, `t[0]='a'` → match → `1 + dp[0][0] = 1`
- `dp[2][4]`: `s[1]='b'`, `t[3]='b'` → match → `1 + dp[1][3] = 1 + 1 = 2`
- `dp[3][3]`: `s[2]='c'`, `t[2]='c'` → match → `1 + dp[2][2] = 1 + 1 = 2`
- `dp[4][5]`: `s[3]='a'`, `t[4]='a'` → match → `1 + dp[3][4] = 1 + 2 = 3`
- `dp[5][5]`: `s[4]='a'`, `t[4]='a'` → match → `1 + dp[4][4] = 1 + 2 = 3`

**`dp[5][5] = 3`** → `LPS(s) = 3` (the palindromic backbone is `"aca"`, exactly as identified by hand earlier).

**Final answer = `n - LPS(s) = 5 - 3 = 2`** ✓ — matches both framings' hand-count of the two leftover characters (`b` and the unpaired `a`) needing insertions.

## Approach — Space Optimization

Identical collapse to LC 516 — the recurrence only ever needs the row directly above and the current row's own earlier entries.

```java
class Solution {
    public int minInsertions(String s) {
        int n = s.length();
        String t = new StringBuilder(s).reverse().toString();

        int[] prev = new int[n + 1];

        for (int i = 1; i <= n; i++) {
            int[] curr = new int[n + 1];

            for (int j = 1; j <= n; j++) {
                if (s.charAt(i - 1) == t.charAt(j - 1)) {
                    curr[j] = 1 + prev[j - 1];
                } else {
                    curr[j] = Math.max(prev[j], curr[j - 1]);
                }
            }

            prev = curr;
        }

        int lps = prev[n];
        return n - lps;
    }
}
```

---

## Complexity Analysis

**Time Complexity — O(n²):**

Building the reversed string costs `O(n)`. The LCS tabulation runs on two strings of length `n` each, so the nested loops give `O(n²)`. The final subtraction is `O(1)`. Total: **O(n²)**, dominated entirely by the LCS computation — exactly the same cost as LC 516 itself, since this problem adds no computational work beyond it.

**Space Complexity — O(n) after optimization:**

Same as LC 516 — full tabulation is `O(n²)`, space-optimized version is `O(n)` using two rolling arrays.
