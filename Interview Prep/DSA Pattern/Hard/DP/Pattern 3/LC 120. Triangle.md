# LC 120. Triangle

---

# Stage 1: Identification

**Step 1 — Which topic?**

You are given a triangular array. Starting from the top (row 0), you need to reach any cell in the bottom row. At each cell (i, j), you can move to (i+1, j) or (i+1, j+1) — straight down or diagonally right. Find the **minimum path sum** from top to bottom.

The moment you see **"find the minimum among all possible paths"** — that is the signal. To find the minimum, you must **try all possible paths**. And whenever you try all possible paths, **Recursion** is your first thought. And when that recursion has overlapping subproblems — it becomes **Dynamic Programming**.

**Why doesn't Greedy work here?**

From (0,0) with value 2, you see (1,0)=3 and (1,1)=4. Greedy picks 3. Then from 3 you see (2,0)=6 and (2,1)=5. Greedy picks 5. Then from 5, forced to pick (3,1)=1. Total = 2+3+5+1 = 11.

But optimal is 2→3→5→1 — wait, that is 11. Let's try: 2→3→5→1=11 vs 2→4→5→1=12 vs 2→3→6→3=14. Actually let me verify: for `[[2],[3,4],[6,5,7],[4,1,8,3]]`:
- Path 2→3→5→1 = 11 ✓ (this is the minimum)

Try a case where greedy fails: `[[2],[3,4],[100,5,7],[4,1,8,3]]`. Greedy picks 3 then 100... total explodes. Optimal would go through 4→5→1=12. **No uniformity in values — greedy fails.**

**Step 2 — Which pattern?**

Input is a triangular 2D structure. Two changing parameters — row `i` and column `j`. The answer at any cell depends on answers from cells in the row below.

That is **Pattern 3: 2D / Grid DP**.

**Step 3 — Which key concept?**

This problem introduces something **new** compared to LC 62, 63, 64:

> **Variable ending point.**

In the previous three problems, both start (0,0) and end (m-1, n-1) were fixed. Here:
- **Start is fixed** → always (0, 0)
- **End is variable** → any column in the last row (n-1, 0), (n-1, 1), ..., (n-1, n-1)

This changes how we set up the recursion. Since we have **one fixed point** (the top) and **multiple possible endpoints** (the entire last row), Striver's preference is to **start recursion from the fixed point (0,0) and go downward** — rather than starting from multiple places in the last row.

# Stage 2: Intuition Building

### The Problem Setup

```
triangle = [
     [2],
    [3, 4],
   [6, 5, 7],
  [4, 1, 8, 3]
]
```

Row 0 has 1 element, row 1 has 2, row 2 has 3, row 3 has 4. At each cell (i, j), valid moves are:
- **(i+1, j)** → straight down
- **(i+1, j+1)** → diagonally right

The last row has indices j = 0, 1, 2, 3. We can end at any of them.

### Why Start from Top (0,0) Instead of Bottom?

In LC 62–64, we started from the **end** (m-1, n-1) and went backward — because there was one fixed end. Here, the end is variable. If we tried to start from the bottom, we would need to call recursion from **every cell in the last row** and take the minimum. That is multiple starting calls.

But the **top is fixed — just one cell (0,0)**. So we start from (0,0) and go **forward/downward** toward the last row. One call gives us the full answer.

### Step 1 — Represent in terms of (i, j)

Define:
```
f(i, j) = minimum path sum starting from cell (i, j)
           all the way to any cell in the last row
```

So the answer we want is `f(0, 0)`.

### Step 2 — Do all possible things at (i, j)

From (i, j), we can go to:
- **Down** → (i+1, j): cost is `triangle[i][j] + f(i+1, j)`
- **Diagonal** → (i+1, j+1): cost is `triangle[i][j] + f(i+1, j+1)`

### Step 3 — Take minimum

We take the **minimum** of the two paths since we want the minimum path sum.

```
f(i, j) = triangle[i][j] + min(f(i+1, j), f(i+1, j+1))
```

### Base Case

**When do we stop?**
When we reach the last row (row n-1). Any cell in the last row is a valid endpoint. Its cost is just its own value — there are no more rows to go down into.

```
if i == n-1 → return triangle[n-1][j]
```

**Is there an out-of-bounds case?**
No! This is a key property of the triangle. If you are at (i, j), both (i+1, j) and (i+1, j+1) always exist within the triangle because row i+1 has i+2 elements (indices 0 to i+1). So j and j+1 are always valid. **No out-of-bounds base case needed.**

### Visualizing the Recursion (4-row triangle)

```
f(0,0) = 2 + min(f(1,0), f(1,1))

f(1,0) = 3 + min(f(2,0), f(2,1))
f(1,1) = 4 + min(f(2,1), f(2,2))
                   ↑
          OVERLAP: f(2,1) called from both f(1,0) and f(1,1)
```

The overlap only gets worse as n grows. Every interior cell of the triangle is reachable by multiple paths from the top.

**Overlapping subproblems confirmed** → DP is needed.

### DP Table Size

Two parameters:
- `i`: row, ranges from 0 to n-1 → **n values**
- `j`: column, ranges from 0 to i (triangle shape) → at most **n values**

dp table: **n × n** (though only the triangular portion is used)

# Stage 3: Coding

## Approach 1 — Pure Recursion (Brute Force)

```java
class Solution {
    public int minimumTotal(List<List<Integer>> triangle) {
        int n = triangle.size();
        return solve(0, 0, n, triangle);
    }

    private int solve(int i, int j, int n, List<List<Integer>> triangle) {
        // Base case: reached the last row
        // This cell is a valid endpoint — return its value
        // WHY return triangle[n-1][j]: last row cells are always in the path,
        //     there's nowhere further to go
        if (i == n - 1) return triangle.get(n - 1).get(j);

        // Move straight down
        int down     = triangle.get(i).get(j) + solve(i + 1, j,     n, triangle);

        // Move diagonally right
        int diagonal = triangle.get(i).get(j) + solve(i + 1, j + 1, n, triangle);

        // Take minimum — we want minimum path sum
        return Math.min(down, diagonal);
    }
}
```

**Time Complexity — O(2^n):**
At every cell, the function makes 2 recursive calls. The depth of the recursion tree is n (number of rows). The total number of nodes grows as 2^n. For n=200 (LeetCode constraint), this is completely impractical.

**Space Complexity — O(n):**
No dp array is allocated. The **recursion call stack** holds one frame per row. The deepest chain goes from row 0 to row n-1, which is n frames deep. Stack uses O(n) space.

## Approach 2 — Memoization (Top-Down DP)

The same cell like (2,1) is computed from both `f(1,0)` and `f(1,1)`. Store each result the first time it is computed.

```java
class Solution {
    public int minimumTotal(List<List<Integer>> triangle) {
        int n = triangle.size();

        // dp[i][j] = -1 means not yet computed
        // triangle is n rows, max n columns per row
        int[][] dp = new int[n][n];
        for (int[] row : dp) {
            Arrays.fill(row, -1);
        }
        return solve(0, 0, n, triangle, dp);
    }

    private int solve(int i, int j, int n,
                      List<List<Integer>> triangle, int[][] dp) {
        // Base case: reached last row
        if (i == n - 1) return triangle.get(n - 1).get(j);

        // Step 1: Already computed? Return stored value instantly
        // WHY: f(2,1) = min path sum starting from (2,1)
        //      This never changes no matter when you call it
        if (dp[i][j] != -1) return dp[i][j];

        // Move straight down
        int down     = triangle.get(i).get(j) + solve(i + 1, j,     n, triangle, dp);

        // Move diagonally right
        int diagonal = triangle.get(i).get(j) + solve(i + 1, j + 1, n, triangle, dp);

        // Step 2: Store before returning
        dp[i][j] = Math.min(down, diagonal);
        return dp[i][j];
    }
}
```

**Time Complexity — O(n²):**
Each unique (i, j) pair is computed exactly once. The triangular shape means the total cells are 1+2+3+...+n = n(n+1)/2 ≈ O(n²). For each cell, O(1) work is done. Total: O(n²).

**Space Complexity — O(n²) + O(n):**
Two sources of space. First, the dp array of size n × n — that is O(n²). Second, the recursion call stack — at most n levels deep. Total: O(n²) + O(n).

## Approach 3 — Tabulation (Bottom-Up DP)

**Key difference from LC 62–64:**
In those problems, recursion went **backward** (from end to start), so tabulation went **forward** (from start to end).

Here, recursion goes **forward** (from row 0 downward), so tabulation goes **backward** (from last row upward). This is the thumb rule:

> **Tabulation is always the opposite direction of recursion.**

**Base case in recursion:** row n-1 → fill dp[n-1][j] = triangle[n-1][j] for all j.

**Then fill from row n-2 down to row 0** — using the recurrence at each cell.

```java
class Solution {
    public int minimumTotal(List<List<Integer>> triangle) {
        int n = triangle.size();
        int[][] dp = new int[n][n];

        // Step 2: Fill base case — last row
        // dp[n-1][j] = triangle[n-1][j] for all valid j
        for (int j = 0; j < n; j++) {
            dp[n - 1][j] = triangle.get(n - 1).get(j);
        }

        // Step 3 & 4: Fill from row n-2 up to row 0
        // WHY i = n-2: row n-1 is already filled as base case
        // WHY i--: tabulation is opposite of recursion (which went i++)
        for (int i = n - 2; i >= 0; i--) {
            // For row i, valid columns are 0 to i (triangle shape)
            // WHY j <= i: row i has exactly i+1 elements (indices 0..i)
            for (int j = i; j >= 0; j--) {
                // Move straight down from (i,j) → (i+1, j)
                int down     = triangle.get(i).get(j) + dp[i + 1][j];

                // Move diagonally from (i,j) → (i+1, j+1)
                int diagonal = triangle.get(i).get(j) + dp[i + 1][j + 1];

                dp[i][j] = Math.min(down, diagonal);
            }
        }

        // Answer: minimum path sum starting from (0,0)
        // WHY dp[0][0]: recursion started at f(0,0) — that's where answer lives
        return dp[0][0];
    }
}
```

**Dry Run (4-row triangle):**
```
triangle = [[2],[3,4],[6,5,7],[4,1,8,3]]

Step 1 — Fill last row (i=3):
dp[3] = [4, 1, 8, 3]

Step 2 — Fill i=2 (valid j: 0,1,2):
dp[2][0] = 6 + min(dp[3][0], dp[3][1]) = 6 + min(4,1) = 6+1 = 7
dp[2][1] = 5 + min(dp[3][1], dp[3][2]) = 5 + min(1,8) = 5+1 = 6
dp[2][2] = 7 + min(dp[3][2], dp[3][3]) = 7 + min(8,3) = 7+3 = 10

dp[2] = [7, 6, 10, 3]   ← 3 is leftover from base case, unused

Step 3 — Fill i=1 (valid j: 0,1):
dp[1][0] = 3 + min(dp[2][0], dp[2][1]) = 3 + min(7,6) = 3+6 = 9
dp[1][1] = 4 + min(dp[2][1], dp[2][2]) = 4 + min(6,10) = 4+6 = 10

dp[1] = [9, 10, _, _]

Step 4 — Fill i=0 (valid j: 0):
dp[0][0] = 2 + min(dp[1][0], dp[1][1]) = 2 + min(9,10) = 2+9 = 11

Answer = dp[0][0] = 11 ✓
```

**Time Complexity — O(n²):**
Two nested loops. Outer runs n-1 times. Inner runs i+1 times for row i. Total iterations = 0+1+2+...+(n-1) = n(n-1)/2 = O(n²). Each iteration does O(1) work.

**Space Complexity — O(n²):**
Only the dp array of size n × n. No recursion stack at all.

## Approach 4 — Space Optimization (The Final Form)

Look at the tabulation code:

```
dp[i][j] = triangle[i][j] + min(dp[i+1][j], dp[i+1][j+1])
```

To compute row `i`, we only need row `i+1`. After computing row `i`, row `i+1` is never needed again.

So keep just **one array of size n** — the "front" row (the row below, already computed). Compute the current row into a separate "curr" array. Then slide: curr becomes the new front.

```
Filling direction (bottom to top):

front = last row = [4, 1, 8, 3]    ← base case

Compute i=2:
curr[0] = 6 + min(front[0], front[1]) = 6 + min(4,1) = 7
curr[1] = 5 + min(front[1], front[2]) = 5 + min(1,8) = 6
curr[2] = 7 + min(front[2], front[3]) = 7 + min(8,3) = 10
front = curr = [7, 6, 10, _]

Compute i=1:
curr[0] = 3 + min(front[0], front[1]) = 3 + min(7,6) = 9
curr[1] = 4 + min(front[1], front[2]) = 4 + min(6,10) = 10
front = curr = [9, 10, _, _]

Compute i=0:
curr[0] = 2 + min(front[0], front[1]) = 2 + min(9,10) = 11
front = curr = [11, _, _, _]

Answer = front[0] = 11 ✓
```

```java
class Solution {
    public int minimumTotal(List<List<Integer>> triangle) {
        int n = triangle.size();

        // front[j] = min path sum starting from (next row, column j)
        // Initialize with last row values — this is the base case
        int[] front = new int[n];
        for (int j = 0; j < n; j++) {
            front[j] = triangle.get(n - 1).get(j);
        }

        // Fill from row n-2 up to row 0
        for (int i = n - 2; i >= 0; i--) {
            // curr[j] = min path sum starting from (current row i, column j)
            int[] curr = new int[n];

            for (int j = i; j >= 0; j--) {
                // Straight down: go to (i+1, j) — front[j]
                // WHY front[j]: front holds row i+1's answers
                int down     = triangle.get(i).get(j) + front[j];

                // Diagonal: go to (i+1, j+1) — front[j+1]
                // WHY front[j+1]: one column right in the row below
                int diagonal = triangle.get(i).get(j) + front[j + 1];

                curr[j] = Math.min(down, diagonal);
            }

            // Slide upward: current row becomes the new "front" for next iteration
            // WHY: when i decreases by 1, what was 'curr' becomes the row below
            front = curr;
        }

        // front[0] holds dp[0][0] — the answer
        return front[0];
    }
}
```

**Time Complexity — O(n²):**
Two nested loops, same iteration count as tabulation. Each cell does O(1) work. Total: O(n²).

**Space Complexity — O(n):**
No n×n array. No recursion stack. Just two arrays of size n — `front` and `curr`. Memory depends only on the number of rows.

## Final Comparison

| Approach | Time | Space | Notes |
|---|---|---|---|
| Pure Recursion | O(2^n) | O(n) stack | Exponential — never use |
| Memoization | O(n²) | O(n²) + O(n) stack | Good interview starting point |
| Tabulation | O(n²) | O(n²) | Better — eliminates stack |
| Space Optimization | O(n²) | **O(n)** | Best — submit this |

## How This Problem Differs from LC 62–64

| Property | LC 62–64 | LC 120 Triangle |
|---|---|---|
| Start point | Fixed (0,0) | Fixed (0,0) |
| End point | Fixed (m-1, n-1) | **Variable** (any cell in last row) |
| Recursion direction | Backward (end → start) | **Forward (start → end)** |
| Tabulation direction | Forward (start → end) | **Backward (end → start)** |
| Out-of-bounds case | Needed | **Not needed** (triangle guarantees validity) |
| Base case | At origin or out-of-bounds | **At last row** |

## The Key Takeaway

```
┌──────────────────────────────────────────────────────────────────┐
│  When start is fixed and end is variable:                        │
│  Start recursion FROM the fixed point, go TOWARD the variable.   │
│  One call gives you the full answer.                             │
│                                                                  │
│  Tabulation is always OPPOSITE to recursion direction:           │
│  Recursion went top → bottom (i++)                               │
│  Tabulation goes bottom → top (i--)                              │
│  Fill the base case (last row) first,                            │
│  then build upward to row 0.                                     │
│                                                                  │
│  Space optimization direction matches tabulation:                │
│  'front' holds the row below (already computed).                 │
│  'curr' holds the row currently being computed.                  │
│  After each row: front = curr, move upward.                      │
│  Answer lives in front[0] after the loop ends.                   │
│                                                                  │
│  No out-of-bounds case needed here — the triangle structure      │
│  guarantees both (i+1,j) and (i+1,j+1) always exist              │
│  for any valid cell (i,j) before the last row.                   │
└──────────────────────────────────────────────────────────────────┘
```
