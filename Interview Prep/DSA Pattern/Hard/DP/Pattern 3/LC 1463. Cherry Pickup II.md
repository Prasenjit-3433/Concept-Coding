# LC 1463. Cherry Pickup II

---

# Stage 1: Identification

**Step 1 — Which topic?**

You are given an `r × c` grid where each cell contains some cherries. Alice starts at **(0, 0)** — the top-left cell. Bob starts at **(0, c-1)** — the top-right cell. Both move simultaneously from row to row downward. From any cell (i, j), they can move to (i+1, j-1), (i+1, j), or (i+1, j+1). If both land on the same cell, the cherries are counted only once. Find the **maximum cherries** both can collect together.

The moment you see **"find the maximum among all possible paths"** — that is the signal. To find the maximum, you must **try all possible paths**. And whenever you try all possible paths, **Recursion** is your first thought. And when that recursion has overlapping subproblems — it becomes **Dynamic Programming**.

**Why doesn't Greedy work here?**

The values in the grid are not uniform. A cell that looks small now might be the gateway to a cell worth thousands later. Greedily picking the largest visible cherry at each step can completely miss a far richer path below. Uniformity is not guaranteed — greedy cannot be applied.

**Step 2 — Which pattern?**

Input is a 2D grid. But here, **two agents move simultaneously**, so we have four changing parameters — (i1, j1) for Alice and (i2, j2) for Bob. As Striver observes: since both move one row downward at every step, i1 and i2 are always equal. So we can collapse to three parameters: **i, j1, j2**.

This is **Pattern 3: 2D / Grid DP** — extended to 3D state space because of the two-agent structure.

**Step 3 — Which key concept?**

The key concept here is **Simultaneous Two-Agent Traversal — reduce to `dp[i][j1][j2]`**.

The critical insight Striver teaches:

> **Do NOT solve Alice and Bob separately and add the results.**
>
> If you compute Alice's best path independently and Bob's best path independently, you have no way to handle the case where they land on the same cell — you'd have to trace back both paths and subtract the overlap. That is expensive and error-prone.
>
> Instead, **move Alice and Bob together in a single recursion**. At every step, try all 9 combinations of their simultaneous moves (3 choices for Alice × 3 choices for Bob). When they land on the same cell, count the cherries once.

This collapses two separate path problems into one unified recurrence.

# Stage 2: Intuition Building

### The Problem Setup

```
grid = [
  [3, 1, 1],    ← row 0: Alice at (0,0)=3, Bob at (0,2)=1
  [2, 5, 1],    ← row 1
  [1, 5, 5],    ← row 2
  [2, 1, 1]     ← row 3
]
```

Alice starts at (0, 0). Bob starts at (0, 2). Both move downward simultaneously. At each step each of them has 3 column choices, giving **3 × 3 = 9 simultaneous move combinations** to try at every row.

### Why collapse i1 and i2 into a single i?

At every step, both Alice and Bob move exactly one row downward — no matter which column direction they choose. So:
- After step 0 → both are in row 0
- After step 1 → both are in row 1
- After step 2 → both are in row 2

Their row indices are **always in sync**. Maintaining i1 and i2 separately would waste a dimension. Striver collapses this to a single `i`, reducing the state from (i1, j1, i2, j2) to **(i, j1, j2)**.

### Step 1 — Represent in terms of (i, j1, j2)

Define:

```
f(i, j1, j2) = maximum cherries Alice and Bob can collect together
               from row i to the last row,
               given Alice is currently at column j1
               and Bob is currently at column j2
```

The answer we want is `f(0, 0, c-1)` — start both at row 0, Alice at column 0, Bob at column c-1.

### Step 2 — Do all possible things at (i, j1, j2)

At row `i`, Alice can move to column j1-1, j1, or j1+1 in row i+1.
Bob can move to column j2-1, j2, or j2+1 in row i+1.

This gives **9 combinations**. Iterate them with two delta loops:

```
for dj1 in {-1, 0, +1}:
    for dj2 in {-1, 0, +1}:
        next state = f(i+1, j1+dj1, j2+dj2)
```

### Step 3 — Take maximum

Among all 9 combinations, take the maximum.

### How to count cherries at the current cell?

At row `i`, Alice is at column j1 and Bob is at column j2.

```
If j1 == j2:
    cherries = grid[i][j1]          ← same cell, count once
Else:
    cherries = grid[i][j1] + grid[i][j2]  ← different cells, count both
```

Add this to the result of the recursive call for the best next state.

### Base Cases

**When i == r-1 (reached the last row):**
We have arrived at the destination. Collect the cherries at the current cells and return — no more rows to process.

```
if i == r-1:
    if j1 == j2: return grid[r-1][j1]
    else: return grid[r-1][j1] + grid[r-1][j2]
```

**Out of bounds:**
If j1 or j2 goes negative or exceeds c-1, that path is invalid. Return a very large negative value so `max()` never picks it.

```
if j1 < 0 || j1 >= c || j2 < 0 || j2 >= c → return -1e9
```

### Visualizing the Overlapping Subproblems

```
grid (3×3):
[3, 1, 1]
[2, 5, 1]
[1, 5, 5]

Start: f(0, 0, 2)
       ↓
tries 9 combos at row 0, including:
   f(1, 0, 1), f(1, 0, 2), f(1, 1, 1), f(1, 1, 2) ...

f(1, 1, 1) can be reached by:
   Alice going right (0→1) + Bob going left (2→1)     from f(0,0,2)
   Alice going right (0→1) + Bob going straight (1→1) from f(0,0,1)  ← if Bob started col 1
   ... multiple paths converge to the same (i, j1, j2) state

OVERLAP: f(1, 1, 1) recomputed from multiple parent states
```

**Overlapping subproblems confirmed** → DP is needed.

### DP Table Size

Three parameters:
- `i`: row, 0 to r-1 → **r values**
- `j1`: Alice's column, 0 to c-1 → **c values**
- `j2`: Bob's column, 0 to c-1 → **c values**

dp table: **r × c × c**

# Stage 3: Coding

## Approach 1 — Pure Recursion (Brute Force)

```java
class Solution {
    public int cherryPickup(int[][] grid) {
        int r = grid.length;
        int c = grid[0].length;
        // Alice starts at (0,0), Bob starts at (0, c-1)
        return solve(0, 0, c - 1, r, c, grid);
    }

    private int solve(int i, int j1, int j2, int r, int c, int[][] grid) {
        // Out of bounds: Alice or Bob crossed left or right boundary
        // Return very large negative so max() never picks this path
        // WHY not 0: returning 0 makes invalid paths look free;
        //            they'd be picked incorrectly as the maximum
        if (j1 < 0 || j1 >= c || j2 < 0 || j2 >= c) return (int) -1e9;

        // Base case: reached the last row — collect cherries and stop
        // WHY handle same-cell case: if both land here, cherries count once
        if (i == r - 1) {
            if (j1 == j2) return grid[i][j1];
            else return grid[i][j1] + grid[i][j2];
        }

        // Collect cherries at current row i
        // WHY same check here: at any intermediate row, same cell = count once
        int cherries;
        if (j1 == j2) {
            cherries = grid[i][j1];
        } else {
            cherries = grid[i][j1] + grid[i][j2];
        }

        // Try all 9 simultaneous move combinations
        // WHY 9: Alice has 3 column choices, Bob has 3 column choices
        //        3 × 3 = 9 combinations to explore at every row
        int maxi = (int) -1e9;
        for (int dj1 = -1; dj1 <= 1; dj1++) {
            for (int dj2 = -1; dj2 <= 1; dj2++) {
                int next = solve(i + 1, j1 + dj1, j2 + dj2, r, c, grid);
                maxi = Math.max(maxi, next);
            }
        }

        // Current cherries + best future result among all 9 paths
        return cherries + maxi;
    }
}
```

**Time Complexity — O(9^r):**
At every row, the function branches into 9 recursive calls. The recursion tree has depth r (number of rows). The total number of nodes grows as 9^r — completely impractical for large r.

**Space Complexity — O(r):**
No dp array is allocated. The recursion call stack holds one frame per row — the deepest chain goes from row 0 down to row r-1, which is r frames deep. Stack uses O(r) space.

## Approach 2 — Memoization (Top-Down DP)

The same state (i, j1, j2) is reached from multiple parent states. For example, `f(1, 1, 1)` can be triggered from `f(0, 0, 2)` via Alice going right and Bob going left, but also from other starting combinations. Store each result the first time.

**3 steps to convert recursion to memoization:**
```
Step 0: Declare dp array of size r × c × c, initialize all to -1
Step 1: Before computing, check — if dp[i][j1][j2] != -1, return it  (lookup)
Step 2: After computing, store — dp[i][j1][j2] = result              (store)
```

```java
class Solution {
    public int cherryPickup(int[][] grid) {
        int r = grid.length;
        int c = grid[0].length;

        // Step 0: dp[i][j1][j2] = -1 means not yet computed
        int[][][] dp = new int[r][c][c];
        for (int[][] layer : dp) {
            for (int[] row : layer) {
                Arrays.fill(row, -1);
            }
        }

        return solve(0, 0, c - 1, r, c, grid, dp);
    }

    private int solve(int i, int j1, int j2, int r, int c,
                      int[][] grid, int[][][] dp) {
        // Out of bounds
        if (j1 < 0 || j1 >= c || j2 < 0 || j2 >= c) return (int) -1e9;

        // Base case: last row
        if (i == r - 1) {
            if (j1 == j2) return grid[i][j1];
            else return grid[i][j1] + grid[i][j2];
        }

        // Step 1: Already computed? Return stored value instantly
        // WHY: f(1,1,1) = max cherries from row 1 with Alice at col 1,
        //      Bob at col 1 — this never changes no matter how we got here
        if (dp[i][j1][j2] != -1) return dp[i][j1][j2];

        // Collect cherries at current row
        int cherries;
        if (j1 == j2) {
            cherries = grid[i][j1];
        } else {
            cherries = grid[i][j1] + grid[i][j2];
        }

        // Try all 9 simultaneous moves
        int maxi = (int) -1e9;
        for (int dj1 = -1; dj1 <= 1; dj1++) {
            for (int dj2 = -1; dj2 <= 1; dj2++) {
                int next = solve(i + 1, j1 + dj1, j2 + dj2, r, c, grid, dp);
                maxi = Math.max(maxi, next);
            }
        }

        // Step 2: Store before returning
        dp[i][j1][j2] = cherries + maxi;
        return dp[i][j1][j2];
    }
}
```

**Time Complexity — O(r × c × c × 9):**
Each unique (i, j1, j2) state is computed exactly once. There are r × c × c unique states. For each state, we run the 3×3 delta loop — 9 operations. Total: O(9 × r × c²). Since 9 is a constant, this is O(r × c²).

**Space Complexity — O(r × c²) + O(r):**
Two sources of space. First, the dp array of size r × c × c. Second, the recursion call stack which goes r levels deep. Total: O(r × c²) + O(r).

## Approach 3 — Tabulation (Bottom-Up DP)

**Key direction observation:**
The recursion goes **downward** (from row 0 toward row r-1). So tabulation goes the **opposite direction** — **upward** (from row r-1 toward row 0).

**Base case in recursion:** row r-1 → fill all (j1, j2) pairs for the last row.

**Then fill from row r-2 upward to row 0** using the recurrence.

```java
class Solution {
    public int cherryPickup(int[][] grid) {
        int r = grid.length;
        int c = grid[0].length;

        int[][][] dp = new int[r][c][c];

        // Step 2: Fill base case — last row (i = r-1)
        // For every (j1, j2) combination at the last row, collect cherries
        for (int j1 = 0; j1 < c; j1++) {
            for (int j2 = 0; j2 < c; j2++) {
                if (j1 == j2) {
                    dp[r - 1][j1][j2] = grid[r - 1][j1];
                } else {
                    dp[r - 1][j1][j2] = grid[r - 1][j1] + grid[r - 1][j2];
                }
            }
        }

        // Step 3 & 4: Fill from row r-2 upward to row 0
        // WHY i = r-2: row r-1 is already filled as base case
        // WHY i--: tabulation goes upward (opposite of recursion which went downward)
        for (int i = r - 2; i >= 0; i--) {
            for (int j1 = 0; j1 < c; j1++) {
                for (int j2 = 0; j2 < c; j2++) {

                    // Collect cherries at current cell (i, j1) and (i, j2)
                    int cherries;
                    if (j1 == j2) {
                        cherries = grid[i][j1];
                    } else {
                        cherries = grid[i][j1] + grid[i][j2];
                    }

                    // Try all 9 simultaneous move combinations
                    int maxi = (int) -1e9;
                    for (int dj1 = -1; dj1 <= 1; dj1++) {
                        for (int dj2 = -1; dj2 <= 1; dj2++) {
                            int nj1 = j1 + dj1;
                            int nj2 = j2 + dj2;

                            // Only consider valid column positions
                            // WHY (int)-1e9 when OOB: make invalid paths
                            //     unattractive so max() never picks them
                            if (nj1 >= 0 && nj1 < c && nj2 >= 0 && nj2 < c) {
                                maxi = Math.max(maxi, dp[i + 1][nj1][nj2]);
                            }
                        }
                    }

                    dp[i][j1][j2] = cherries + maxi;
                }
            }
        }

        // Answer: Alice starts at col 0, Bob starts at col c-1, row 0
        return dp[0][0][c - 1];
    }
}
```

**Time Complexity — O(r × c² × 9):**
Three nested loops (r × c × c) for the states, plus the inner 3×3 delta loop (9 iterations). Total: O(9 × r × c²) = O(r × c²).

**Space Complexity — O(r × c²):**
Only the dp array of size r × c × c. No recursion stack at all.

## Approach 4 — Space Optimization (The Final Form)

Look at the tabulation recurrence:

```
dp[i][j1][j2] depends on dp[i+1][j1+dj1][j2+dj2]
```

To compute row `i`, we only ever look at row `i+1`. After computing row `i`, row `i+1` is never needed again.

So instead of the full r × c × c array, keep just **two 2D arrays of size c × c** — `front` (row i+1, already computed) and `curr` (row i, being computed). After each row, `curr` becomes the new `front`.

```java
class Solution {
    public int cherryPickup(int[][] grid) {
        int r = grid.length;
        int c = grid[0].length;

        // front[j1][j2] = max cherries from row below,
        //                  with Alice at col j1 and Bob at col j2
        // Initialize with last row values — this is the base case
        int[][] front = new int[c][c];
        for (int j1 = 0; j1 < c; j1++) {
            for (int j2 = 0; j2 < c; j2++) {
                if (j1 == j2) {
                    front[j1][j2] = grid[r - 1][j1];
                } else {
                    front[j1][j2] = grid[r - 1][j1] + grid[r - 1][j2];
                }
            }
        }

        // Fill from row r-2 upward to row 0
        for (int i = r - 2; i >= 0; i--) {
            // curr[j1][j2] = max cherries from row i onward,
            //                 Alice at col j1, Bob at col j2
            int[][] curr = new int[c][c];

            for (int j1 = 0; j1 < c; j1++) {
                for (int j2 = 0; j2 < c; j2++) {

                    // Collect cherries at current row i
                    int cherries;
                    if (j1 == j2) {
                        cherries = grid[i][j1];
                    } else {
                        cherries = grid[i][j1] + grid[i][j2];
                    }

                    // Try all 9 simultaneous move combinations
                    int maxi = (int) -1e9;
                    for (int dj1 = -1; dj1 <= 1; dj1++) {
                        for (int dj2 = -1; dj2 <= 1; dj2++) {
                            int nj1 = j1 + dj1;
                            int nj2 = j2 + dj2;

                            // WHY front[nj1][nj2]: front holds the row below
                            //     (row i+1) which is already computed
                            if (nj1 >= 0 && nj1 < c && nj2 >= 0 && nj2 < c) {
                                maxi = Math.max(maxi, front[nj1][nj2]);
                            }
                        }
                    }

                    curr[j1][j2] = cherries + maxi;
                }
            }

            // Slide upward: current row becomes the new front for next iteration
            // WHY: when i decreases by 1, what was 'curr' becomes the row below
            front = curr;
        }

        // front[0][c-1] = answer for Alice at col 0, Bob at col c-1, row 0
        return front[0][c - 1];
    }
}
```

Same nested loops as tabulation. No change in time complexity — O(r × c²).

**Space Complexity — O(c²):**
No r × c × c array. No recursion stack. Just two 2D arrays of size c × c — `front` and `curr`. Memory depends only on the number of columns, not the number of rows.

## The Key Takeaway

```
┌──────────────────────────────────────────────────────────────────┐
│  When two agents traverse simultaneously:                        │
│                                                                  │
│  1. NEVER solve them separately and add the results.             │
│     Separate solutions cannot handle overlapping cells.          │
│                                                                  │
│  2. Move them TOGETHER in one unified recurrence.                │
│     At each step, try all 9 combinations of moves                │
│     (3 choices for agent 1 × 3 choices for agent 2).             │
│                                                                  │
│  3. Collapse synchronized dimensions.                            │
│     Both agents move one row at a time →                         │
│     i1 == i2 always → store a single i.                          │
│     State goes from (i1, j1, i2, j2) → (i, j1, j2).              │
│     3D DP — not more complex, just one extra dimension.          │
│                                                                  │
│  4. Same-cell rule: if j1 == j2, count cherries only once.       │
│     Apply this check at EVERY row — base case and otherwise.     │
│                                                                  │
│  Space optimization:                                             │
│  dp[i][...][...] uses only dp[i+1][...][...]                     │
│  → replace r×c×c array with two c×c arrays (front + curr).       │
│  Slide upward after each row: front = curr.                      │
│  Answer lives in front[0][c-1] after the loop ends.              │
└──────────────────────────────────────────────────────────────────┘
```
