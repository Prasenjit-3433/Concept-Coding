# Maximum Path Sum in a Matrix (GFG / Coding Ninjas)

---

# Stage 1: Identification

**Step 1 — Which topic?**

You are given an n × m matrix filled with integers. You need to find the **maximum path sum** starting from **any cell in the first row** and ending at **any cell in the last row**. From any cell (i, j), you can move to exactly three cells in the row below: directly down (i+1, j), diagonally left (i+1, j-1), or diagonally right (i+1, j+1).

The moment you see **"find the maximum among all possible paths"** — that is the signal. To find the maximum, you must **try all possible paths**. And whenever you try all possible paths, **Recursion** is your first thought. And when that recursion has overlapping subproblems — it becomes **Dynamic Programming**.

**Why doesn't Greedy work here?**

Consider this matrix:

```
 1   2   10   4
 8   1    3   2
 3   7    2   1
```

Greedy from row 0: pick 10 (maximum in first row). From 10, move down to 3 (only option directly below). From 3, move down to 2. Total = 10 + 3 + 2 = 15.

But the actual optimal path is: start at 2 (row 0, col 1) → go to 1 (row 1, col 1) → wait, actually:

```
Start at 1 (col 0) → 8 (col 0) → 7 (col 1) → total = 16
```

Greedy missed this because it fixated on 10 in the first row without seeing what lay beneath it. **The values are not uniform.** There might be a cell with value 20,000 deep below a cell that looks modest in row 0. Greedily picking the largest value at each step can close off the path to something far larger later. You must try all paths.

**Step 2 — Which pattern?**

Input is a 2D matrix. Two changing parameters — row `i` and column `j`. The answer at any cell depends on answers from cells in the row below.

That is **Pattern 3: 2D / Grid DP**.

**Step 3 — Which key concept?**

This problem introduces the **third and hardest variant** of Grid DP:

```
LC 62, LC 63, LC 64  →  Fixed start (0,0),   Fixed end (m-1, n-1)
LC 120 Triangle      →  Fixed start (0,0),   Variable end (any cell in last row)
This problem         →  Variable start,       Variable end
                        (any cell in row 0)   (any cell in last row)
```

When **both** start and end are variable, you cannot just call a single `f(destination)`. You need to call the recursion for **every possible ending cell** and take the maximum across all of them.

The trick Striver teaches: **write the recurrence going upward** — start from the last row, recurse upward to row 0. Then call `f(n-1, j)` for every column `j` and take the maximum. This way each call represents "what is the maximum path sum if I end at cell (n-1, j)?", and the overall answer is the max across all those calls.

# Stage 2: Intuition Building

### The Problem Setup

```
matrix = [
  [ 1,  2, 10,  4],   ← row 0 (any cell can be the start)
  [ 8,  1,  3,  2],   ← row 1
  [ 3,  7,  2,  1]    ← row 2 (any cell can be the end)
]
```

From any cell (i, j), three moves are allowed going **downward**:
- Straight down → (i+1, j)
- Diagonal left → (i+1, j-1)
- Diagonal right → (i+1, j+1)

### Why can't we just call f(0, j) for each j and go downward?

We could. But Striver's preferred approach across all Grid DP problems is to **go backward** — start from the destination and recurse toward the source. The reason: when the destination is variable (multiple ending cells), we loop over all of them and take the max. When the source is also variable, the recursion naturally handles it — once we recurse from a fixed ending cell all the way to row 0, the base case simply returns whatever value is at row 0, regardless of which column we land in. That handles the variable start automatically.

### Step 1 — Represent in terms of (i, j)

Define:

```
f(i, j) = maximum path sum to reach cell (i, j)
           starting from ANY cell in row 0
```

So we call `f(n-1, j)` for every `j` from 0 to m-1, and take the maximum across all those calls.

### Step 2 — Do all possible things at (i, j)

Since we are going **upward** (from last row toward row 0), from cell (i, j) we ask: which cells in row i-1 could have led here?

Going downward, a cell can move straight, diag-left, or diag-right. So going backward, cell (i, j) could have been reached from:
- **(i-1, j)** — the cell directly above (straight down move)
- **(i-1, j-1)** — the cell above-left (diagonal right move led here)
- **(i-1, j+1)** — the cell above-right (diagonal left move led here)

At cell (i, j), we always include `matrix[i][j]` in the path sum. So:

```
up        = matrix[i][j] + f(i-1, j)
left-diag = matrix[i][j] + f(i-1, j-1)
right-diag = matrix[i][j] + f(i-1, j+1)
```

### Step 3 — Take maximum

The question asks for **maximum** path sum, so:

```
f(i, j) = matrix[i][j] + max(up, left-diag, right-diag)
```

### Base Cases

**When i == 0:**
We have reached the first row — this is the "source" side. Any cell here is a valid starting point. Just return the value at that cell.
```
if i == 0 → return matrix[0][j]
```

**Out of bounds:**
When going to (i-1, j-1) or (i-1, j+1), the column might go negative or exceed m-1. Since we are looking for a maximum, an out-of-bounds path must be made **unattractive** — return a very large negative number so `max()` never picks it.
```
if j < 0 OR j >= m → return -1e9
```

Note: the row never goes out of bounds going upward because the base case catches i == 0 before i goes to -1.

### Visualizing the Overlapping Subproblems

```
matrix = [
  [1, 2, 10],
  [9, 6,  3],
  [2, 7,  4]
]

Call f(2,0):  reaches f(1,0), f(1,1)  (no f(1,-1) — out of bounds)
Call f(2,1):  reaches f(1,0), f(1,1), f(1,2)
Call f(2,2):  reaches f(1,1), f(1,2)  (no f(1,3) — out of bounds)
                        ↑
              f(1,0) computed in both f(2,0) and f(2,1)
              f(1,1) computed in f(2,0), f(2,1), AND f(2,2)
              f(1,2) computed in both f(2,1) and f(2,2)
```

Every interior cell is reachable from multiple cells in the row below. The overlapping gets worse as n and m grow.

**Overlapping subproblems confirmed** → DP is needed.

### DP Table Size

Two parameters:
- `i`: row, ranges from 0 to n-1 → **n values**
- `j`: column, ranges from 0 to m-1 → **m values**

dp table: **n × m**

# Stage 3: Coding

## Approach 1 — Pure Recursion (Brute Force)

```java
class Solution {
    public int maxPathSum(int[][] matrix) {
        int n = matrix.length;
        int m = matrix[0].length;

        int maxi = Integer.MIN_VALUE;

        // Call f(n-1, j) for every column in the last row
        // WHY: both start and end are variable — we try all ending cells
        //      and take the maximum across all of them
        for (int j = 0; j < m; j++) {
            maxi = Math.max(maxi, solve(n - 1, j, matrix, m));
        }

        return maxi;
    }

    private int solve(int i, int j, int[][] matrix, int m) {
        // Out of bounds: column went negative or exceeded last column
        // Return very large negative so max() never picks this path
        // WHY not 0: returning 0 would make out-of-bounds paths look free,
        //            and they'd be chosen incorrectly as the maximum
        if (j < 0 || j >= m) return (int) -1e9;

        // Base case: reached row 0 — this is a valid starting cell
        // Return its value to include it in the path sum
        if (i == 0) return matrix[0][j];

        // Move straight up
        int up = matrix[i][j] + solve(i - 1, j, matrix, m);

        // Move diagonally up-left
        int leftDiag = matrix[i][j] + solve(i - 1, j - 1, matrix, m);

        // Move diagonally up-right
        int rightDiag = matrix[i][j] + solve(i - 1, j + 1, matrix, m);

        // Take maximum — we want maximum path sum
        return Math.max(up, Math.max(leftDiag, rightDiag));
    }
}
```

**Time Complexity — O(3^n):**
At every cell, the function makes 3 recursive calls — up, left diagonal, right diagonal. The recursion tree branches into 3 at every level. The depth of the tree is n (number of rows). So in the worst case, the total number of nodes in the tree grows as 3^n. For n = 100, this is astronomically large. Completely impractical.

**Space Complexity — O(n):**
No dp array is allocated. But the **recursion call stack** holds frames — the deepest chain goes from row n-1 all the way up to row 0. That is n frames simultaneously on the stack. Stack uses O(n) space.

## Approach 2 — Memoization (Top-Down DP)

As shown in the overlapping subproblem analysis, `f(1,1)` gets called from three different cells in row 2 when we loop over all ending columns. Store each result the first time.

**3 steps to convert recursion to memoization:**
```
Step 0: Declare dp array of size n × m, initialize all to -1
Step 1: Before computing, check — if dp[i][j] != -1, return it   (lookup)
Step 2: After computing, store — dp[i][j] = result               (store)
```

```java
class Solution {
    public int maxPathSum(int[][] matrix) {
        int n = matrix.length;
        int m = matrix[0].length;

        // Step 0: dp[i][j] = -1 means not yet computed
        int[][] dp = new int[n][m];
        for (int[] row : dp) {
            Arrays.fill(row, -1);
        }

        int maxi = Integer.MIN_VALUE;
        for (int j = 0; j < m; j++) {
            maxi = Math.max(maxi, solve(n - 1, j, matrix, m, dp));
        }

        return maxi;
    }

    private int solve(int i, int j, int[][] matrix, int m, int[][] dp) {
        // Out of bounds
        if (j < 0 || j >= m) return (int) -1e9;

        // Base case: row 0
        if (i == 0) return matrix[0][j];

        // Step 1: Already computed? Return stored value instantly
        // WHY: f(1,1) = max path sum to reach (1,1) from any cell in row 0
        //      This never changes no matter which ending cell triggered this call
        if (dp[i][j] != -1) return dp[i][j];

        int up        = matrix[i][j] + solve(i - 1, j,     matrix, m, dp);
        int leftDiag  = matrix[i][j] + solve(i - 1, j - 1, matrix, m, dp);
        int rightDiag = matrix[i][j] + solve(i - 1, j + 1, matrix, m, dp);

        // Step 2: Store before returning
        dp[i][j] = Math.max(up, Math.max(leftDiag, rightDiag));
        return dp[i][j];
    }
}
```

**Time Complexity — O(n × m):**
Each unique (i, j) pair is computed exactly once. There are n × m unique cells. For each cell, O(1) work is done — three option computations and a max. Total: O(n × m).

**Space Complexity — O(n × m) + O(n):**
Two sources of space. First, the dp array of size n × m. Second, the recursion call stack — the deepest chain goes n levels deep before hitting row 0. Total: O(n × m) + O(n).

## Approach 3 — Tabulation (Bottom-Up DP)

**Key observation about direction:**
The recursion goes **upward** (from row n-1 toward row 0). So tabulation goes the **opposite direction** — **downward** (from row 0 toward row n-1). This is the thumb rule: tabulation is always opposite to recursion direction.

**Base case in recursion:** row 0 → fill `dp[0][j] = matrix[0][j]` for all j.

**Then fill from row 1 down to row n-1** using the recurrence.

```java
class Solution {
    public int maxPathSum(int[][] matrix) {
        int n = matrix.length;
        int m = matrix[0].length;

        int[][] dp = new int[n][m];

        // Step 2: Fill base case — row 0
        // WHY: row 0 is the source; every cell there is a valid starting point
        for (int j = 0; j < m; j++) {
            dp[0][j] = matrix[0][j];
        }

        // Step 3 & 4: Fill from row 1 down to row n-1
        // WHY i starts at 1: row 0 is already filled as base case
        // WHY i++: tabulation goes downward (opposite of recursion which went upward)
        for (int i = 1; i < n; i++) {
            for (int j = 0; j < m; j++) {

                // Straight up: cell directly above
                int up = matrix[i][j] + dp[i - 1][j];

                // Diagonal up-left: only valid if j-1 >= 0
                // WHY (int)-1e9 when out of bounds: make this path unattractive
                //     so max() never picks it; avoids ArrayIndexOutOfBoundsException
                int leftDiag = (int) -1e9;
                if (j - 1 >= 0) {
                    leftDiag = matrix[i][j] + dp[i - 1][j - 1];
                }

                // Diagonal up-right: only valid if j+1 < m
                int rightDiag = (int) -1e9;
                if (j + 1 < m) {
                    rightDiag = matrix[i][j] + dp[i - 1][j + 1];
                }

                dp[i][j] = Math.max(up, Math.max(leftDiag, rightDiag));
            }
        }

        // Answer: maximum among all cells in the last row
        // WHY: any cell in the last row is a valid ending point
        int maxi = Integer.MIN_VALUE;
        for (int j = 0; j < m; j++) {
            maxi = Math.max(maxi, dp[n - 1][j]);
        }

        return maxi;
    }
}
```

**Dry Run (3×3 matrix):**
```
matrix = [
  [ 1,  2, 10],
  [ 9,  6,  3],
  [ 2,  7,  4]
]

Step 1 — Fill row 0 (base case):
dp[0] = [1, 2, 10]

Step 2 — Fill row 1:
dp[1][0]: up=9+1=10, leftDiag=-1e9(OOB), rightDiag=9+2=11  → max=11
dp[1][1]: up=6+2=8,  leftDiag=6+1=7,     rightDiag=6+10=16 → max=16
dp[1][2]: up=3+10=13, leftDiag=3+2=5,    rightDiag=-1e9(OOB)→ max=13

dp[1] = [11, 16, 13]

Step 3 — Fill row 2:
dp[2][0]: up=2+11=13, leftDiag=-1e9(OOB), rightDiag=2+16=18 → max=18
dp[2][1]: up=7+16=23, leftDiag=7+11=18,   rightDiag=7+13=20 → max=23
dp[2][2]: up=4+13=17, leftDiag=4+16=20,   rightDiag=-1e9(OOB)→ max=20

dp[2] = [18, 23, 20]

Answer = max(18, 23, 20) = 23 ✓
```

**Time Complexity — O(n × m):**
Two nested loops — outer runs n-1 times, inner runs m times. Each cell does O(1) work. Plus one final loop of m for finding the maximum in the last row. Total: O(n × m) + O(m) = O(n × m).

**Space Complexity — O(n × m):**
Only the dp array of size n × m. No recursion stack at all.

## Approach 4 — Space Optimization (The Final Form)

Look at the tabulation recurrence:

```
dp[i][j] = matrix[i][j] + max(dp[i-1][j], dp[i-1][j-1], dp[i-1][j+1])
```

To compute any cell in row `i`, we only ever look at three cells — all from row `i-1`. Row `i-1` is the only dependency. After computing row `i`, row `i-1` is never needed again.

So instead of keeping the entire n × m array, keep just **one array of size m** for the previous row, and compute each current row into a fresh array of size m. After each row, the current becomes the new previous.

```java
class Solution {
    public int maxPathSum(int[][] matrix) {
        int n = matrix.length;
        int m = matrix[0].length;

        // prev[j] = max path sum to reach (previous row, column j)
        //           starting from any cell in row 0
        // Initialize with row 0 values — this is the base case
        int[] prev = new int[m];
        for (int j = 0; j < m; j++) {
            prev[j] = matrix[0][j];
        }

        // Fill from row 1 down to row n-1
        for (int i = 1; i < n; i++) {
            // curr[j] = max path sum to reach (current row i, column j)
            int[] curr = new int[m];

            for (int j = 0; j < m; j++) {
                // Straight up: previous row, same column
                // WHY prev[j]: prev holds row i-1's answers
                int up = matrix[i][j] + prev[j];

                // Diagonal up-left: previous row, column j-1
                // WHY (int)-1e9 when OOB: same reason as tabulation
                int leftDiag = (int) -1e9;
                if (j - 1 >= 0) {
                    leftDiag = matrix[i][j] + prev[j - 1];
                }

                // Diagonal up-right: previous row, column j+1
                int rightDiag = (int) -1e9;
                if (j + 1 < m) {
                    rightDiag = matrix[i][j] + prev[j + 1];
                }

                curr[j] = Math.max(up, Math.max(leftDiag, rightDiag));
            }

            // Slide downward: current row becomes the new previous row
            // WHY: next iteration's "row above" is this iteration's curr
            prev = curr;
        }

        // prev now holds the last computed row (row n-1)
        // Answer is the maximum among all cells in this last row
        int maxi = Integer.MIN_VALUE;
        for (int j = 0; j < m; j++) {
            maxi = Math.max(maxi, prev[j]);
        }

        return maxi;
    }
}
```

**Dry Run (space optimized):**
```

  [ 1,  2, 10],
  [ 9,  6,  3],
  [ 2,  7,  4]
]

prev = [1, 2, 10]   ← base case (row 0)

i = 1:
curr[0]: up=9+1=10,  leftDiag=OOB,   rightDiag=9+2=11  → 11
curr[1]: up=6+2=8,   leftDiag=6+1=7, rightDiag=6+10=16 → 16
curr[2]: up=3+10=13, leftDiag=3+2=5, rightDiag=OOB     → 13
prev = [11, 16, 13]

curr[1]: up=7+16=23, leftDiag=7+11=18,rightDiag=7+13=20 → 23
curr[2]: up=4+13=17, leftDiag=4+16=20,rightDiag=OOB     → 20
prev = [18, 23, 20]

Answer = max(18, 23, 20) = 23 ✓
```

**Time Complexity — O(n × m):**
Two nested loops with the same iteration count as tabulation. One final loop of size m. Total: O(n × m). No change from tabulation.

**Space Complexity — O(m):**
No n × m array. No recursion stack. Just two arrays of size m — `prev` and `curr`. Memory depends only on the number of columns, not the number of rows.

## How This Problem Differs from Previous Grid DP Problems

| Property | LC 62–64 | LC 120 Triangle | Max Path Sum in Matrix |
|---|---|---|---|
| Start point | Fixed (0,0) | Fixed (0,0) | **Variable** (any cell in row 0) |
| End point | Fixed (m-1,n-1) | **Variable** (any cell in last row) | **Variable** (any cell in last row) |
| Recursion direction | Backward | Forward | **Backward (upward)** |
| Tabulation direction | Forward | Backward | **Forward (downward)** |
| Answer | Single dp value | dp[0][0] | **max over last row** |
| Out-of-bounds returns | 0 (counting) or 1e9 (minimizing) | Not needed | **-1e9** (maximizing) |

## The Key Takeaway

```
┌──────────────────────────────────────────────────────────────────┐
│  When BOTH start and end are variable:                           │
│                                                                  │
│  Fix one side as the recursion destination.                      │
│  Loop over all possibilities on that side,                       │
│  call the recursion for each, and take the best result.          │
│                                                                  │
│  Here: fix the ending side (last row).                           │
│  Call f(n-1, j) for every j.                                     │
│  The variable start (row 0) is handled automatically             │
│  by the base case — it just returns matrix[0][j]                 │
│  for whichever column the path lands in.                         │
│                                                                  │
│  Out-of-bounds rule for optimization problems:                   │
│  Maximizing → return -1e9   (make invalid paths repulsive)       │
│  Minimizing → return +1e9   (make invalid paths repulsive)       │
│  Counting   → return 0      (don't add invalid paths to count)   │
│                                                                  │
│  Space optimization rule:                                        │
│  Whenever dp[i][j] uses only dp[i-1][...],                       │
│  replace the full n×m array with two arrays of size m.           │
│  prev holds the row above, curr holds the current row.           │
│  After each row: prev = curr, slide downward.                    │
│  Answer = max over prev after the loop ends.                     │
└──────────────────────────────────────────────────────────────────┘
```

# LC 931. Minimum Falling Path Sum

---

# Stage 1: Identification

**Step 1 — Which topic?**

You are given an n × n matrix. You need to find the **minimum sum** of any falling path through the matrix. A falling path starts from **any cell in the first row** and ends at **any cell in the last row**. From cell (i, j), you can move to (i+1, j-1), (i+1, j), or (i+1, j+1) — the three cells directly below.

The moment you see **"find the minimum among all possible paths"** — that is the signal. To find the minimum, you must **try all possible paths**. And whenever you try all possible paths, **Recursion** is your first thought. And when that recursion has overlapping subproblems — it becomes **Dynamic Programming**.

**Step 2 — Which pattern?**

Input is a 2D square matrix. Two changing parameters — row `i` and column `j`. The answer at any cell depends on cells in the adjacent row.

That is **Pattern 3: 2D / Grid DP**.

**Step 3 — Which key concept?**

If you have just read the Maximum Path Sum problem above, you have already seen this entire pattern. LC 931 is **structurally identical** — variable start, variable end, three diagonal moves, loop over all ending cells and take the best result.

The **only two differences** are:

```
Max Path Sum  →  maximize,  rectangular n×m matrix
LC 931        →  minimize,  square n×n matrix
```

This means:
- `max()` becomes `min()`
- Out-of-bounds returns `-1e9` becomes `+1e9`
- The final answer is `min over last row` instead of `max over last row`

Everything else — recurrence structure, base cases, memoization, tabulation, space optimization — is identical.

---

# Stage 2: Intuition Building

### The Problem Setup

```
matrix = [
  [ 2,  1,  3],   ← row 0 (any cell can be the start)
  [ 6,  5,  4],   ← row 1
  [ 7,  8,  9]    ← row 2 (any cell can be the end)
]
```

From (i, j), valid moves downward are:
- Straight down → (i+1, j)
- Diagonal left → (i+1, j-1)
- Diagonal right → (i+1, j+1)

### Step 1 — Represent in terms of (i, j)

Define:

```
f(i, j) = minimum path sum to reach cell (i, j)
           starting from ANY cell in row 0
```

Call `f(n-1, j)` for every column j in the last row, and take the minimum across all of them.

### Step 2 — Do all possible things at (i, j)

Going **upward** (backwards), cell (i, j) could have been reached from:
- (i-1, j) — straight down move
- (i-1, j-1) — diagonal right move
- (i-1, j+1) — diagonal left move

```
up        = matrix[i][j] + f(i-1, j)
leftDiag  = matrix[i][j] + f(i-1, j-1)
rightDiag = matrix[i][j] + f(i-1, j+1)
```

### Step 3 — Take minimum

```
f(i, j) = matrix[i][j] + min(up, leftDiag, rightDiag)
```

### Base Cases

```
if i == 0         → return matrix[0][j]   (valid source cell)
if j < 0 || j >= n → return +1e9          (out of bounds, unattractive for min)
```

### Verifying with the Example

```
matrix = [[2,1,3],[6,5,4],[7,8,9]]

f(0,0)=2, f(0,1)=1, f(0,2)=3   ← base case

f(1,0): up=6+2=8, leftDiag=OOB=1e9, rightDiag=6+1=7  → 7
f(1,1): up=5+1=6, leftDiag=5+2=7,   rightDiag=5+3=8  → 6
f(1,2): up=4+3=7, leftDiag=4+1=5,   rightDiag=OOB     → 5

f(2,0): up=7+7=14, leftDiag=OOB,    rightDiag=7+6=13 → 13
f(2,1): up=8+6=14, leftDiag=8+7=15, rightDiag=8+5=13 → 13
f(2,2): up=9+5=14, leftDiag=9+6=15, rightDiag=OOB    → 14

Answer = min(13, 13, 14) = 13 ✓
```

# Stage 3: Coding

Since the structure is identical to Maximum Path Sum, the code mirrors it exactly — with `min` replacing `max` and `+1e9` replacing `-1e9`.

## Approach 1 — Pure Recursion (Brute Force)

```java
class Solution {
    public int minFallingPathSum(int[][] matrix) {
        int n = matrix.length;

        int mini = Integer.MAX_VALUE;

        // Call f(n-1, j) for every column in the last row
        // WHY: both start and end are variable — try all ending cells,
        //      take the minimum across all of them
        for (int j = 0; j < n; j++) {
            mini = Math.min(mini, solve(n - 1, j, matrix, n));
        }

        return mini;
    }

    private int solve(int i, int j, int[][] matrix, int n) {
        // Out of bounds: column went negative or exceeded last column
        // Return very large positive so min() never picks this path
        // WHY not 0: returning 0 would make out-of-bounds paths look free,
        //            and they'd always be chosen incorrectly as the minimum
        if (j < 0 || j >= n) return (int) 1e9;

        // Base case: reached row 0 — valid starting cell
        // Return its value to include it in the path sum
        if (i == 0) return matrix[0][j];

        // Move straight up
        int up = matrix[i][j] + solve(i - 1, j, matrix, n);

        // Move diagonally up-left
        int leftDiag = matrix[i][j] + solve(i - 1, j - 1, matrix, n);

        // Move diagonally up-right
        int rightDiag = matrix[i][j] + solve(i - 1, j + 1, matrix, n);

        // Take minimum — we want minimum path sum
        return Math.min(up, Math.min(leftDiag, rightDiag));
    }
}
```

**Time Complexity — O(3^n):**
At every cell, the function makes 3 recursive calls. The recursion tree branches 3 ways at every level, and has depth n (number of rows). Total nodes in the tree grow as 3^n — exponential and completely impractical for large n.

**Space Complexity — O(n):**
No dp array is used. The recursion call stack holds one frame per row — the deepest chain goes from row n-1 all the way up to row 0, which is n frames deep. Stack uses O(n) space.

## Approach 2 — Memoization (Top-Down DP)

```java
class Solution {
    public int minFallingPathSum(int[][] matrix) {
        int n = matrix.length;

        // Step 0: dp[i][j] = -1 means not yet computed
        int[][] dp = new int[n][n];
        for (int[] row : dp) {
            Arrays.fill(row, -1);
        }

        int mini = Integer.MAX_VALUE;
        for (int j = 0; j < n; j++) {
            mini = Math.min(mini, solve(n - 1, j, matrix, n, dp));
        }

        return mini;
    }

    private int solve(int i, int j, int[][] matrix, int n, int[][] dp) {
        // Out of bounds
        if (j < 0 || j >= n) return (int) 1e9;

        // Base case: row 0
        if (i == 0) return matrix[0][j];

        // Step 1: Already computed? Return stored value instantly
        // WHY: f(1,1) = min path sum to reach (1,1) from any cell in row 0
        //      This never changes no matter which ending cell triggered this call
        if (dp[i][j] != -1) return dp[i][j];

        int up        = matrix[i][j] + solve(i - 1, j,     matrix, n, dp);
        int leftDiag  = matrix[i][j] + solve(i - 1, j - 1, matrix, n, dp);
        int rightDiag = matrix[i][j] + solve(i - 1, j + 1, matrix, n, dp);

        // Step 2: Store before returning
        dp[i][j] = Math.min(up, Math.min(leftDiag, rightDiag));
        return dp[i][j];
    }
}
```

**Time Complexity — O(n²):**
Each unique (i, j) pair is computed exactly once. The matrix is n × n, so there are n² unique cells. For each cell, O(1) work is done. Total: O(n²).

**Space Complexity — O(n²) + O(n):**
Two sources of space — the dp array of size n × n, and the recursion call stack which goes n levels deep. Total: O(n²) + O(n).

## Approach 3 — Tabulation (Bottom-Up DP)

```java
class Solution {
    public int minFallingPathSum(int[][] matrix) {
        int n = matrix.length;
        int[][] dp = new int[n][n];

        // Step 2: Fill base case — row 0
        for (int j = 0; j < n; j++) {
            dp[0][j] = matrix[0][j];
        }

        // Step 3 & 4: Fill from row 1 down to row n-1
        for (int i = 1; i < n; i++) {
            for (int j = 0; j < n; j++) {

                // Straight up
                int up = matrix[i][j] + dp[i - 1][j];

                // Diagonal up-left: only valid if j-1 >= 0
                // WHY (int)1e9 when OOB: make this path unattractive
                //     so min() never picks it
                int leftDiag = (int) 1e9;
                if (j - 1 >= 0) {
                    leftDiag = matrix[i][j] + dp[i - 1][j - 1];
                }

                // Diagonal up-right: only valid if j+1 < n
                int rightDiag = (int) 1e9;
                if (j + 1 < n) {
                    rightDiag = matrix[i][j] + dp[i - 1][j + 1];
                }

                dp[i][j] = Math.min(up, Math.min(leftDiag, rightDiag));
            }
        }

        // Answer: minimum among all cells in the last row
        int mini = Integer.MAX_VALUE;
        for (int j = 0; j < n; j++) {
            mini = Math.min(mini, dp[n - 1][j]);
        }

        return mini;
    }
}
```

**Time Complexity — O(n²):**
Two nested loops — outer runs n-1 times, inner runs n times. Each cell does O(1) work. One final loop of n for the answer. Total: O(n²).

**Space Complexity — O(n²):**
Only the dp array of size n × n. No recursion stack.

## Approach 4 — Space Optimization (The Final Form)

```java
class Solution {
    public int minFallingPathSum(int[][] matrix) {
        int n = matrix.length;

        // prev[j] = min path sum to reach (previous row, column j)
        //           starting from any cell in row 0
        int[] prev = new int[n];
        for (int j = 0; j < n; j++) {
            prev[j] = matrix[0][j];
        }

        for (int i = 1; i < n; i++) {
            int[] curr = new int[n];

            for (int j = 0; j < n; j++) {
                // Straight up
                // WHY prev[j]: prev holds row i-1's min path sums
                int up = matrix[i][j] + prev[j];

                // Diagonal up-left
                int leftDiag = (int) 1e9;
                if (j - 1 >= 0) {
                    leftDiag = matrix[i][j] + prev[j - 1];
                }

                // Diagonal up-right
                int rightDiag = (int) 1e9;
                if (j + 1 < n) {
                    rightDiag = matrix[i][j] + prev[j + 1];
                }

                curr[j] = Math.min(up, Math.min(leftDiag, rightDiag));
            }

            // Slide downward: current row becomes the new previous row
            // WHY: next iteration needs this row as its "row above"
            prev = curr;
        }

        // prev now holds the last row's minimum path sums
        // Answer is the minimum among all of them
        int mini = Integer.MAX_VALUE;
        for (int j = 0; j < n; j++) {
            mini = Math.min(mini, prev[j]);
        }

        return mini;
    }
}
```

**Time Complexity — O(n²):**
Two nested loops, same iteration count as tabulation. Final loop of n. Total: O(n²).

**Space Complexity — O(n):**
No n × n array. No recursion stack. Just two arrays of size n — `prev` and `curr`.
