# LC 70. Climbing Stairs

---

# Stage 1: Identification

**Step 1 — Which topic?**

You are at stair 0 and need to reach stair n. At each step you can either climb 1 stair or 2 stairs. You need to count the total number of distinct ways to reach stair n.

The moment you see **"count the total number of ways"** — that is the clearest signal. To count all ways, you need to **try all possible ways**. And whenever you have to try all possible ways, **Recursion** is your first thought. And once you have overlapping subproblems in that recursion — that becomes **Dynamic Programming**.

**Step 2 — Which pattern?**

Ask yourself — what is the input? A single number `n`. What are you computing? A single value that depends on a constant number of previous values. No grid, no two sequences, no tree.

That is **Pattern 1: 1D DP (Linear)**.

**Step 3 — Which key concept?**

To derive the recurrence, Striver gives you a **3-step shortcut** that works for every DP problem:

```
Step 1: Represent the problem in terms of index
Step 2: Do all possible things on that index (per the problem statement)
Step 3: If count all ways → sum up all results
        If find minimum  → take min of all results
        If find maximum  → take max of all results
```

Apply this here and you will discover that this problem **reduces to Fibonacci**. The key concept is the same **base template recurrence** from LC 509 — just dressed in a different story.

# Stage 2: Intuition Building

### Step 1 — Represent the problem in terms of index

Think of each stair as an index: stair 0, stair 1, stair 2, ... stair n.

You are currently at index 0. You need to reach index n.

Now define what your recursion should return:

```
f(n) = number of distinct ways to reach stair n from stair 0
```

Or equivalently — think top-down:

```
f(n) = number of distinct ways to reach stair n
       (considering you can come from stair n-1 or stair n-2)
```

### Step 2 — Do all possible things on that index

The problem says: at each stair, you can take **1 step** or **2 steps**.

So from stair `n`, you could have arrived from:
- Stair `n-1` (by taking 1 step), OR
- Stair `n-2` (by taking 2 steps)

So the number of ways to reach stair `n` = ways to reach `n-1` + ways to reach `n-2`.

That gives you the recurrence:

```
f(n) = f(n-1) + f(n-2)
```

### Step 3 — Sum up because we're counting all ways

Since the question asks to **count** all distinct ways, you **sum** the results of the two choices.

### Identifying the base cases

What is the smallest meaningful input?

- **f(0) = 1** → You are already at stair 0. There is exactly 1 way to be here — do nothing. This is the base truth.
- **f(1) = 1** → From stair 0, take one step. Only 1 way.

What about `f(2)`? Let's verify manually:
- Take 1 step + 1 step
- Take 2 steps directly

That's 2 ways. And `f(1) + f(0) = 1 + 1 = 2` ✓

What about `f(3)`?
- 1+1+1
- 1+2
- 2+1

That's 3 ways. And `f(2) + f(1) = 2 + 1 = 3` ✓

**This is exactly the Fibonacci recurrence.** The problem looks completely different on the surface — stairs, climbing, steps — but strip away the story and the mathematical structure is identical to Fibonacci.

This is what Striver means when he says: *"I did not know this was Fibonacci. But I followed the 3-step shortcut and arrived at the same recurrence."* The shortcut is more powerful than memorizing what problems look like Fibonacci.

### Why does naive recursion have a problem here?

Draw the recursion tree for `n = 5`:

```
                        f(5)
                      /      \
                  f(4)          f(3)
                 /    \        /    \
             f(3)     f(2)  f(2)   f(1)
            /    \    /  \   /  \
          f(2)  f(1) f(1)f(0)f(1)f(0)
          /  \
        f(1) f(0)
```

`f(3)` computed twice. `f(2)` computed three times. `f(1)` computed five times. This is **overlapping subproblems** — the defining property that tells you DP is needed.

# Stage 3: Coding

## Approach 1 — Pure Recursion (Brute Force)

```java
class Solution {
    public int climbStairs(int n) {
        // Base cases
        if (n == 0) return 1; // already at destination, 1 way
        if (n == 1) return 1; // only one step possible
        
        // From stair n, you arrived from either n-1 or n-2
        return climbStairs(n - 1) + climbStairs(n - 2);
    }
}
```

**Time Complexity — O(2^n):**
At every call, the function makes 2 recursive calls. So the call tree is a binary tree of depth n. The total number of nodes in this tree is approximately 2^n. For n = 45 (the constraint on this problem), that's 2^45 ≈ 35 trillion operations. Completely impractical.

**Space Complexity — O(n):**
There is no array being used. But recursion uses the **call stack**. At any point in time, the deepest chain of calls goes from `f(n)` → `f(n-1)` → `f(n-2)` → ... → `f(0)`. That chain has n frames on the stack simultaneously. So the recursion stack uses O(n) space.

---

## Approach 2 — Memoization (Top-Down DP)

The 3 steps to convert recursion to memoization:
- **Step 0:** Declare a `dp` array of size `n+1`, fill everything with `-1` (meaning "not yet computed")
- **Step 1:** Before computing, check — if `dp[n] != -1`, return `dp[n]` immediately
- **Step 2:** After computing, store the result — `dp[n] = result`

```java
class Solution {
    public int climbStairs(int n) {
        // Step 0: dp array, -1 means not yet computed
        int[] dp = new int[n + 1];
        Arrays.fill(dp, -1);
        return solve(n, dp);
    }
    
    private int solve(int n, int[] dp) {
        // Base cases — same as pure recursion
        if (n == 0) return 1;
        if (n == 1) return 1;
        
        // Step 1: Already computed? Return stored value instantly
        // WHY: f(3) is always the same value no matter when you call it.
        //      No reason to recompute it.
        if (dp[n] != -1) return dp[n];
        
        // Step 2: Compute and store before returning
        // WHY: Next time someone asks for f(n), the answer is ready
        dp[n] = solve(n - 1, dp) + solve(n - 2, dp);
        
        return dp[n];
    }
}
```

**Time Complexity — O(n):**
Without memoization, the same subproblem like `f(3)` gets recomputed many times. With memoization, each unique subproblem from `f(0)` to `f(n)` is computed **exactly once**. There are n+1 unique subproblems and each does O(1) work. So total time is O(n).

**Space Complexity — O(n) + O(n):**
Two sources of space are being used here. First, the `dp` array of size n+1 — that is O(n). Second, the recursion call stack — the deepest chain of calls still goes n levels deep before hitting a base case, so that is another O(n). Total space is O(n) but with a larger constant than tabulation.

---

## Approach 3 — Tabulation (Bottom-Up DP)

Instead of starting at `f(n)` and going down, start from the base cases and build upward. The recipe:

```
Step 1: Declare dp array, same size as memoization
Step 2: Fill in the base cases directly
Step 3: Look at the recurrence — figure out the starting index
        (recurrence needs i-1 and i-2, so valid from i=2 onwards)
Step 4: Fill from that index up to n
```

```java
class Solution {
    public int climbStairs(int n) {
        if (n <= 1) return 1;
        
        // Step 1: Declare dp array
        int[] dp = new int[n + 1];
        
        // Step 2: Fill base cases directly
        // WHY: These are the ground truths — no recursion needed for these
        dp[0] = 1;
        dp[1] = 1;
        
        // Step 3 & 4: Fill using recurrence from i=2 onwards
        // WHY start at 2: we need dp[i-1] and dp[i-2],
        //                  both of which must already be filled
        for (int i = 2; i <= n; i++) {
            dp[i] = dp[i - 1] + dp[i - 2];
            // WHY: ways to reach stair i = ways from stair i-1 + ways from stair i-2
        }
        
        return dp[n];
    }
}
```

**Time Complexity — O(n):**
A single `for` loop runs from `i = 2` to `i = n`. That is n-1 iterations, each doing O(1) work. So total time is O(n). Same as memoization, but the constant is smaller because there is no function call overhead.

**Space Complexity — O(n):**
The `dp` array of size n+1 uses O(n) space. Unlike memoization, there is **no recursion stack** here. Everything is iterative. So the total space is just O(n) — already an improvement over memoization's O(n) + O(n).

## Approach 4 — Space Optimization (The Final Form)

Look at the recurrence: `dp[i] = dp[i-1] + dp[i-2]`.

To compute `dp[i]`, you only need the **previous two values**. The entire array is never needed at once. So instead of keeping the whole array, just keep two variables and slide them forward.

```
Before loop:
    prev2 = dp[0] = 1
    prev1 = dp[1] = 1

i = 2: curr = prev1 + prev2 = 1 + 1 = 2
       prev2 = prev1 = 1
       prev1 = curr  = 2

i = 3: curr = prev1 + prev2 = 2 + 1 = 3
       prev2 = prev1 = 2
       prev1 = curr  = 3

i = 4: curr = prev1 + prev2 = 3 + 2 = 5
       prev2 = prev1 = 3
       prev1 = curr  = 5

Answer = prev1 = 5 ✓  (for n=4, there are 5 ways)
```

```java
class Solution {
    public int climbStairs(int n) {
        if (n <= 1) return 1;
        
        // Only two variables — no array needed at all
        int prev2 = 1;  // dp[0] = 1
        int prev1 = 1;  // dp[1] = 1
        
        for (int i = 2; i <= n; i++) {
            int curr = prev1 + prev2;
            // WHY: same recurrence as before,
            //      just using variable names instead of array indices
            
            prev2 = prev1;
            // WHY: in the next iteration, what is dp[i-1] will become dp[i-2]
            
            prev1 = curr;
            // WHY: what we just computed becomes dp[i-1] in the next iteration
        }
        
        // prev1 now holds dp[n]
        return prev1;
    }
}
```

**Time Complexity — O(n):**
Still a single loop from `i = 2` to `i = n`. Same O(n) as tabulation. No change here.

**Space Complexity — O(1):**
This is the win. No array is allocated. No recursion stack. Just three integer variables — `prev2`, `prev1`, and `curr` — regardless of how large n is. Whether n is 10 or 10 million, the memory used stays constant. That is what O(1) space means.

## Final Comparison

| Approach | Time | Space | Notes |
|---|---|---|---|
| Pure Recursion | O(2^n) | O(n) stack | Exponential — never use |
| Memoization | O(n) | O(n) array + O(n) stack | Good interview starting point |
| Tabulation | O(n) | O(n) array | Better — eliminates stack |
| Space Optimization | O(n) | **O(1)** | Best — submit this |
