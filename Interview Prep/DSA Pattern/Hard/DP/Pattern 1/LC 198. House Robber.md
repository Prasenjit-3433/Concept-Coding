# LC 198. House Robber

---

# Stage 1: Identification

**Step 1 — Which topic?**

You are given an array of non-negative integers representing the amount of money in each house. You cannot rob two adjacent houses. You need to find the **maximum sum** you can rob.

The moment you see **"maximum sum from a subsequence with no adjacent elements"** — that is the signal. To find the best among all possible ways, you must **try all possible ways**. And whenever you try all possible ways, **Recursion** is your first thought. And when that recursion has overlapping subproblems — it becomes **Dynamic Programming**.

**Why doesn't Greedy work here?**

You might think — at each house, just pick the one with more money. But greedy fails. Consider:

```
houses = [2, 1, 1, 2]
```

Greedily pick index 0 (value 2), then skip index 1, pick index 2 (value 1), total = 3. But the optimal is picking index 0 and index 3 — total = 4. A greedy choice now can miss a better combination later. You must try all ways.

**Step 2 — Which pattern?**

Input is a single array. You are computing a single value that depends on a constant number of previous states in that array.

That is **Pattern 1: 1D DP (Linear)**.

**Step 3 — Which key concept?**

Apply Striver's **3-step shortcut**:

```
Step 1: Represent problem in terms of index
Step 2: Do all possible things on that index
        → Pick this element OR don't pick it (the pick/not-pick technique)
Step 3: Question says maximum → take max of all results
```

The constraint **"no adjacent"** changes only one thing in the pick step: instead of going to `index - 1`, you go to `index - 2` (because `index - 1` is now forbidden).

# Stage 2: Intuition Building

### Step 1 — Represent the problem in terms of index

Treat each house as an index: 0, 1, 2, ... n-1.

Define your recursion as:

```
f(index) = maximum money you can rob from houses 0 to index
           with no two adjacent houses robbed
```

So the answer you want is `f(n-1)`.

### Step 2 — Do all possible things on that index

At any index, you have exactly two choices:

**Choice 1 — Pick (rob this house):**
You take `nums[index]`. But now you cannot rob `index - 1`. So the next call jumps back to `index - 2`.

```
pick = nums[index] + f(index - 2)
```

**Choice 2 — Not pick (skip this house):**
You don't rob this house. The previous house (`index - 1`) is still available for consideration.

```
notPick = 0 + f(index - 1)
```

### Step 3 — Take maximum because question asks for maximum sum

```
f(index) = max(pick, notPick)
         = max(nums[index] + f(index-2),  f(index-1))
```

### Base cases

```
f(0) = nums[0]
```
Only one house available. Best you can do is rob it.

```
f(negative) = 0
```
If index goes below 0 (happens when you're at index 1 and try index-2 = -1), return 0 — nothing to rob.

### Verify with example

```
nums = [2, 1, 4, 9]
```

- `f(0) = 2`
- `f(1) = max(nums[1] + f(-1), f(0)) = max(1 + 0, 2) = max(1, 2) = 2`
- `f(2) = max(nums[2] + f(0), f(1)) = max(4 + 2, 2) = max(6, 2) = 6`
- `f(3) = max(nums[3] + f(1), f(2)) = max(9 + 2, 6) = max(11, 6) = 11`

Answer = 11 ✓ (rob houses at index 1 and index 3: values 2 and 9, or index 0 and index 2 and... wait, let's check: 2+9=11 via index 0 and 3, or 2+4=6 via index 0 and 2, or 1+9=10. Best is 2+9=11 ✓)

### Are there overlapping subproblems?

Draw the recursion tree for `nums = [2, 1, 4, 9]`:

```
                    f(3)
                  /      \
              f(1)          f(2)
             /    \        /    \
          f(-1)  f(0)   f(0)   f(1)
          [0]    [2]    [2]   /    \
                           f(-1) f(0)
                           [0]   [2]
```

`f(1)` computed twice. `f(0)` computed three times. **Overlapping subproblems confirmed** → DP is needed.

# Stage 3: Coding

## Approach 1 — Pure Recursion (Brute Force)

```java
class Solution {
    public int rob(int[] nums) {
        int n = nums.length;
        return solve(n - 1, nums);
    }
    
    private int solve(int index, int[] nums) {
        // Base case: only one house, rob it
        if (index == 0) return nums[0];
        
        // Base case: index went negative (tried index-2 from index=1)
        // Nothing to rob, return 0
        if (index < 0) return 0;
        
        // Choice 1: Pick — rob this house
        // Then jump back 2 because index-1 is now off limits
        int pick = nums[index] + solve(index - 2, nums);
        
        // Choice 2: Not pick — skip this house
        // Previous house index-1 is still available
        int notPick = solve(index - 1, nums);
        
        // Take the maximum because we want maximum money
        return Math.max(pick, notPick);
    }
}
```

**Time Complexity — O(2^n):**
At every index, the function makes 2 recursive calls — one for `index-2` (pick) and one for `index-1` (not pick). The recursion tree is a binary tree of depth n. The total number of nodes grows as 2^n. For n = 100 houses, that is 2^100 — completely impractical.

**Space Complexity — O(n):**
No array is used. But the **recursion call stack** holds frames. The deepest chain of calls in the not-pick direction goes `f(n-1)` → `f(n-2)` → `f(n-3)` → ... → `f(0)`. That is n frames on the stack simultaneously. So call stack uses O(n) space.

## Approach 2 — Memoization (Top-Down DP)

The same subproblems are solved repeatedly. Store each result the first time it is computed. Three steps:

```
Step 0: Declare dp array of size n, fill with -1
Step 1: Before computing, check — if dp[index] != -1, return dp[index]  (lookup)
Step 2: After computing, store — dp[index] = result                      (store)
```

```java
class Solution {
    public int rob(int[] nums) {
        int n = nums.length;
        // Step 0: dp array, -1 means not yet computed
        int[] dp = new int[n];
        Arrays.fill(dp, -1);
        return solve(n - 1, nums, dp);
    }
    
    private int solve(int index, int[] nums, int[] dp) {
        // Base cases — same as pure recursion
        if (index == 0) return nums[0];
        if (index < 0) return 0;
        
        // Step 1: Already computed? Return stored value instantly
        // WHY: f(1) gives maximum money from houses 0 to 1 — this
        //      never changes no matter how many times you call it.
        //      No reason to recompute it.
        if (dp[index] != -1) return dp[index];
        
        // Choice 1: Rob this house, jump back 2
        int pick = nums[index] + solve(index - 2, nums, dp);
        
        // Choice 2: Skip this house, go to index-1
        int notPick = solve(index - 1, nums, dp);
        
        // Step 2: Store before returning
        // WHY: Next time solve(index) is called, answer is ready in O(1)
        dp[index] = Math.max(pick, notPick);
        
        return dp[index];
    }
}
```

**Time Complexity — O(n):**
Without memoization, `f(1)` might be recomputed many times deep inside the recursion tree. With memoization, each unique index from 0 to n-1 is computed **exactly once**. Every subsequent call for the same index hits the `dp[index] != -1` check and returns in O(1). There are n unique subproblems, each doing O(1) work. Total: O(n).

**Space Complexity — O(n) + O(n):**
Two sources of space. First, the `dp` array of size n — that is O(n). Second, the **recursion call stack** — even with memoization, the first chain of calls in the not-pick direction goes n levels deep before hitting the base case. So stack uses another O(n). Total space: O(n) array + O(n) stack. An improvement in time over pure recursion, but the stack is still there.

## Approach 3 — Tabulation (Bottom-Up DP)

Flip the direction. Start from the base case and build upward to the answer. No recursion stack at all.

The recipe:
```
Step 1: Declare dp array of size n
Step 2: Fill base case directly — dp[0] = nums[0]
Step 3: Look at recurrence — figure out starting index
        (needs index-1 and index-2, so valid from index=1 onwards)
Step 4: Fill from index=1 to n-1 using the recurrence
```

One edge case to handle: when `i = 1`, the pick option goes to `i - 2 = -1`. That is a negative index — out of bounds. So handle it with a condition.

```java
class Solution {
    public int rob(int[] nums) {
        int n = nums.length;
        
        // Step 1: Declare dp array
        int[] dp = new int[n];
        
        // Step 2: Base case — only house 0 available, rob it
        dp[0] = nums[0];
        
        // Step 3 & 4: Fill from index=1 to n-1
        for (int i = 1; i < n; i++) {
            
            // Choice 1: Pick — rob house i
            // Add dp[i-2] only if i >= 2, otherwise i-2 is out of bounds
            // When i = 1, pick from index -1 would be out of bounds → treat as 0
            int pick = nums[i];
            if (i >= 2) {
                pick += dp[i - 2];
            }
            // WHY: if we're at i=1 and pick, we came from i-2=-1 which is nothing
            //      so we add 0. If i>=2, we add what was best up to i-2.
            
            // Choice 2: Not pick — best we had up to previous house
            int notPick = dp[i - 1];
            
            // Store the best choice at index i
            dp[i] = Math.max(pick, notPick);
        }
        
        // Answer is the best we can do across all n houses
        return dp[n - 1];
    }
}
```

**Time Complexity — O(n):**
A single `for` loop from `i = 1` to `i = n-1`. That is n-1 iterations, each doing O(1) work — compute pick, compute notPick, take max. Total: O(n). Same as memoization but no function call overhead at all.

**Space Complexity — O(n):**
Only the `dp` array of size n. No recursion stack. Everything is iterative. Already an improvement — O(n) vs the O(n) + O(n) of memoization.

## Approach 4 — Space Optimization (The Final Form)

Look at the recurrence at any index `i`:

```
dp[i] = max(nums[i] + dp[i-2],  dp[i-1])
```

To compute `dp[i]`, you only need **dp[i-1]** and **dp[i-2]**. Nothing before that. So the entire array is never needed at once. Keep just two variables and slide them forward.

Watch the pattern:

```
At index i:
    prev2 represents dp[i-2]
    prev1 represents dp[i-1]
    curr  represents dp[i]

After computing curr, slide forward:
    prev2 = prev1    ← what was dp[i-1] becomes dp[i-2] for next iteration
    prev1 = curr     ← what we just computed becomes dp[i-1] for next iteration
```

Visualizing the window on `nums = [2, 1, 4, 9]`:

```
prev2 = 0 (treated as dp[-1] = 0, nothing before index 0)
prev1 = nums[0] = 2   (dp[0] = 2)

i = 1:
    pick    = nums[1] + prev2 = 1 + 0 = 1
    notPick = prev1 = 2
    curr    = max(1, 2) = 2
    prev2 = 2, prev1 = 2

i = 2:
    pick    = nums[2] + prev2 = 4 + 2 = 6
    notPick = prev1 = 2
    curr    = max(6, 2) = 6
    prev2 = 2, prev1 = 6

i = 3:
    pick    = nums[3] + prev2 = 9 + 2 = 11
    notPick = prev1 = 6
    curr    = max(11, 6) = 11
    prev2 = 6, prev1 = 11

Answer = prev1 = 11 ✓
```

```java
class Solution {
    public int rob(int[] nums) {
        int n = nums.length;
        
        // prev2 = dp[i-2], initialized as 0 (nothing before index 0)
        // prev1 = dp[i-1], initialized as dp[0] = nums[0]
        int prev2 = 0;
        int prev1 = nums[0];
        
        for (int i = 1; i < n; i++) {
            // Choice 1: Rob house i
            // prev2 represents best up to i-2 (the last non-adjacent house)
            int pick = nums[i] + prev2;
            
            // Choice 2: Skip house i
            // prev1 represents best up to i-1
            int notPick = prev1;
            
            int curr = Math.max(pick, notPick);
            
            // Slide the window forward
            prev2 = prev1;
            // WHY: what was dp[i-1] becomes dp[i-2] in the next iteration
            
            prev1 = curr;
            // WHY: what we just computed becomes dp[i-1] in the next iteration
        }
        
        // prev1 now holds dp[n-1] — the final answer
        return prev1;
    }
}
```

**Time Complexity — O(n):**
Still a single loop from `i = 1` to `i = n-1`. Same O(n) as tabulation. Each iteration does O(1) work — compute pick, notPick, curr, and slide two variables. No change in time complexity.

**Space Complexity — O(1):**
No array allocated. No recursion stack. Just three integer variables — `prev2`, `prev1`, `curr` — regardless of how large n is. Whether there are 10 houses or 10 million, memory stays constant. That is O(1).

## Final Comparison

| Approach | Time | Space | Notes |
|---|---|---|---|
| Pure Recursion | O(2^n) | O(n) stack | Exponential — never use |
| Memoization | O(n) | O(n) array + O(n) stack | Good interview starting point |
| Tabulation | O(n) | O(n) array | Better — eliminates stack |
| Space Optimization | O(n) | **O(1)** | Best — submit this |

## The Key Takeaway

```
┌──────────────────────────────────────────────────────────────────┐
│  The Pick / Not-Pick technique:                                  │
│                                                                  │
│  At every index, you have exactly two choices:                   │
│    Pick:     take nums[index], jump to index-2                   │
│    Not Pick: skip nums[index], go to index-1                     │
│                                                                  │
│  The "no adjacent" constraint changes ONLY the pick step:        │
│    Normal subsequence → pick goes to index-1                     │
│    No adjacent → pick goes to index-2 (skip one)                 │
│                                                                  │
│  Space optimization thumb rule (applies to all 1D DP):           │
│  If recurrence uses only (i-1) and (i-2),                        │
│  replace the entire dp array with just two variables.            │
│  prev2 slides to where prev1 was.                                │
│  prev1 slides to where curr was.                                 │
│  This pattern repeats in every 1D DP problem that follows.       │
└──────────────────────────────────────────────────────────────────┘
```
