# LC 746. Min Cost Climbing Stairs

---

# Stage 1: Identification

**Step 1 — Which topic?**

You are given an array `cost` where `cost[i]` is the cost of stepping on stair `i`. You can start from either stair `0` or stair `1`. From any stair, you can climb **1 step or 2 steps**. You need to reach **beyond the last stair** (i.e., past index `n-1`), and you want to do this while paying the **minimum total cost**.

The moment you see **"find the minimum among all possible ways"** — that is the signal. To find the minimum, you must **try all possible ways**. And whenever you try all possible ways, **Recursion** is your first thought. And when that recursion has overlapping subproblems — it becomes **Dynamic Programming**.

**Why doesn't Greedy work here?**

You might think — always take the cheaper of the two steps available. But greedy fails. Consider:

```
cost = [10, 1, 1, 10]
```

Greedily from stair 0: stair 0 costs 10, but jumping 2 steps skips it and lands on stair 1 (cost 1). From stair 1, jump 2 steps to land past stair 3 — but wait, that means paying for stair 1 only. Total = 1.

But if you started from stair 0 instead (paying 10) just because it looked "available first," you'd end up paying much more. The point: **which stair you commit to now determines what's reachable later, and you cannot tell in advance which starting point or which jump size leads to the cheapest total.** You must try all ways and take the minimum.

**Step 2 — Which pattern?**

Input is a single array. You are computing a single value (minimum cost) that depends on a constant number of previous values in that array.

That is **Pattern 1: 1D DP (Linear)**.

**Step 3 — Which key concept?**

This problem is a direct extension of **Frog Jump** — same "jump 1 or jump 2" structure. But there are two twists that make this problem worth its own note:

```
Twist 1: You don't pay for the stair you LAND on to finish —
         you pay for the stair you JUMPED FROM.

Twist 2: The "destination" isn't the last stair — it's ONE STEP
         PAST the last stair. The array has an implicit extra
         position beyond its own length that costs 0.
```

Apply Striver's **3-step shortcut**:

```
Step 1: Represent problem in terms of index
Step 2: Do all possible things on that index
Step 3: Question says minimum → take min of all results
```

# Stage 2: Intuition Building

### Step 1 — Represent the problem in terms of index

Think of the "top" — the position just past the last stair — as index `n` (where `n = cost.length`). This position is free to stand on; you don't pay anything once you're there, because the problem only charges you when you **step off** a stair, not when you arrive somewhere.

Define:

```
f(i) = minimum cost to reach index i, starting from stair 0 or stair 1
```

The answer you want is `f(n)` — the cost to reach the position just past the last stair.

### Step 2 — Do all possible things on that index

To reach stair `i`, you must have jumped from **either** stair `i-1` (a 1-step jump) **or** stair `i-2` (a 2-step jump). Whichever one you jumped from, you had to **pay that stair's cost** to leave it.

So:

```
f(i) = min(
    f(i-1) + cost[i-1],   ← came from i-1, paid to leave i-1
    f(i-2) + cost[i-2]    ← came from i-2, paid to leave i-2
)
```

**Why `cost[i-1]` and not `cost[i]`?** This is the detail that trips people up. You are asking "what did it cost me to arrive at `i`" — and the charge happens at the stair you departed from, not the one you're standing on now. If you're computing `f(i)`, you have already left `i-1` or `i-2` behind; the cost of that stair is a completed transaction, and it belongs to the step you just took, not to `i` itself.

### Step 3 — Take minimum because question asks for minimum cost

Since we want the cheapest way to arrive, we take the `min` of the two options.

### Base cases

You are told you may **start** at stair 0 or stair 1, for free — no cost to simply stand at the starting point before you've made any jump.

```
f(0) = 0   (standing at stair 0, haven't jumped yet — no cost incurred)
f(1) = 0   (standing at stair 1, haven't jumped yet — no cost incurred)
```

This is a different flavor of base case than Frog Jump, where `f(0) = 0` was the *only* base case. Here, **both** starting points are valid and free, because the problem explicitly lets you choose either one to begin.

### Verify with example

```
cost = [10, 15, 20]
n = 3
```

```
f(0) = 0
f(1) = 0
f(2) = min(f(1) + cost[1], f(0) + cost[0]) = min(0+15, 0+10) = 10
f(3) = min(f(2) + cost[2], f(1) + cost[1]) = min(10+20, 0+15) = 15
```

Answer = `f(3) = 15` ✓ (start at stair 1 for free, jump 2 steps past the end — cost 15)

### Are there overlapping subproblems?

Draw the recursion tree for `f(4)`:

```
                      f(4)
                    /      \
                f(3)          f(2)
               /    \        /    \
           f(2)     f(1)  f(1)   f(0)
          /    \
       f(1)   f(0)
```

`f(2)` is computed twice. `f(1)` is computed three times. **Overlapping subproblems confirmed** → DP is needed.

# Stage 3: Coding

## Approach 1 — Pure Recursion (Brute Force)

```java
class Solution {
    public int minCostClimbingStairs(int[] cost) {
        int n = cost.length;
        return solve(n, cost);
    }
    
    private int solve(int i, int[] cost) {
        // Base case: standing at stair 0 or stair 1 costs nothing —
        // both are valid free starting points
        if (i == 0 || i == 1) return 0;
        
        // Option 1: arrived here by jumping from i-1 (1-step jump)
        // WHY cost[i-1]: you pay to LEAVE i-1, not to land on i
        int oneStep = solve(i - 1, cost) + cost[i - 1];
        
        // Option 2: arrived here by jumping from i-2 (2-step jump)
        int twoStep = solve(i - 2, cost) + cost[i - 2];
        
        // Take minimum because question asks for minimum cost
        return Math.min(oneStep, twoStep);
    }
}
```

**Time Complexity — O(2^n):**
At every index, the function makes 2 recursive calls. The recursion tree is a binary tree of depth n. Total nodes grow as 2^n. For n = 1000 (a realistic constraint), this is completely impractical.

**Space Complexity — O(n):**
No array is used, but the **recursion call stack** holds frames. The deepest chain of calls goes `f(n)` → `f(n-1)` → ... → `f(1)` — that is n frames on the stack simultaneously. So the call stack uses O(n) space.

---

## Approach 2 — Memoization (Top-Down DP)

The same subproblem like `f(2)` might be recomputed many times. Store each result the first time it's computed. Three steps:

```
Step 0: Declare dp array of size n+1, fill with -1
Step 1: If dp[i] != -1, return it immediately  (lookup)
Step 2: Before returning, store result in dp[i]  (store)
```

```java
class Solution {
    public int minCostClimbingStairs(int[] cost) {
        int n = cost.length;
        
        // Step 0: dp array, -1 means not yet computed
        int[] dp = new int[n + 1];
        Arrays.fill(dp, -1);
        
        return solve(n, cost, dp);
    }
    
    private int solve(int i, int[] cost, int[] dp) {
        // Base case
        if (i == 0 || i == 1) return 0;
        
        // Step 1: Already computed? Return stored value instantly
        // WHY: f(4) is always the minimum cost to reach stair 4 —
        //      it never changes no matter how many times you ask for it
        if (dp[i] != -1) return dp[i];
        
        int oneStep = solve(i - 1, cost, dp) + cost[i - 1];
        int twoStep = solve(i - 2, cost, dp) + cost[i - 2];
        
        // Step 2: Store before returning
        dp[i] = Math.min(oneStep, twoStep);
        
        return dp[i];
    }
}
```

**Time Complexity — O(n):**
Without memoization, `f(2)` might be recomputed many times. With memoization, each unique index from `0` to `n` is computed **exactly once**. Every subsequent call for the same index hits the `dp[i] != -1` check and returns instantly in O(1). There are n+1 unique subproblems, each doing O(1) work. Total: O(n).

**Space Complexity — O(n) + O(n):**
Two sources of space. First, the `dp` array of size n+1 — that is O(n). Second, the **recursion call stack** — even with memoization, the first call chain still goes from `f(n)` down to `f(1)`, which is n frames deep. So total space is O(n) array + O(n) stack.

## Approach 3 — Tabulation (Bottom-Up DP)

Flip the direction. Instead of starting at `f(n)` and going down, start from the base cases and build upward to `f(n)`. No recursion stack at all.

The recipe:
```
Step 1: Declare dp array of size n+1
Step 2: Fill in base cases — dp[0] = 0, dp[1] = 0
Step 3: Look at recurrence — figure out starting index
        (needs i-1 and i-2, so valid from i=2 onwards)
Step 4: Fill from i=2 to n using the recurrence
```

```java
class Solution {
    public int minCostClimbingStairs(int[] cost) {
        int n = cost.length;
        
        // Step 1: Declare dp array
        int[] dp = new int[n + 1];
        
        // Step 2: Base cases — both starting stairs are free
        dp[0] = 0;
        dp[1] = 0;
        
        // Step 3 & 4: Fill using recurrence from i=2 to n
        // WHY start at 2: recurrence needs i-1 and i-2,
        //                  both must already be filled
        for (int i = 2; i <= n; i++) {
            int oneStep = dp[i - 1] + cost[i - 1];
            int twoStep = dp[i - 2] + cost[i - 2];
            dp[i] = Math.min(oneStep, twoStep);
        }
        
        return dp[n];
    }
}
```

**Dry Run (`cost = [10, 15, 20]`):**
```
n = 3
dp[0] = 0
dp[1] = 0

i=2: dp[2] = min(dp[1]+cost[1], dp[0]+cost[0]) = min(0+15, 0+10) = 10
i=3: dp[3] = min(dp[2]+cost[2], dp[1]+cost[1]) = min(10+20, 0+15) = 15

Answer = dp[3] = 15 ✓
```

**Time Complexity — O(n):**
A single `for` loop runs from `i = 2` to `i = n`. That is n-1 iterations, each doing O(1) work — two option computations and a min. Total: O(n). Same as memoization but with no function call overhead — cleaner in practice.

**Space Complexity — O(n):**
Only the `dp` array of size n+1. No recursion stack at all — everything is iterative.

## Approach 4 — Space Optimization (The Final Form)

Look at the recurrence: `dp[i] = min(dp[i-1] + cost[i-1], dp[i-2] + cost[i-2])`.

To compute `dp[i]`, you only need **dp[i-1]** and **dp[i-2]**. Nothing before that is ever touched again. So there is no reason to keep the entire array — just slide two variables forward.

```
Before loop:
    prev2 = dp[0] = 0
    prev1 = dp[1] = 0

i = 2:
    curr = min(prev1 + cost[1], prev2 + cost[0])
    slide: prev2 = prev1, prev1 = curr

i = 3:
    curr = min(prev1 + cost[2], prev2 + cost[1])
    slide: prev2 = prev1, prev1 = curr

... and so on
```

```java
class Solution {
    public int minCostClimbingStairs(int[] cost) {
        int n = cost.length;
        
        // prev2 = dp[i-2], prev1 = dp[i-1]
        int prev2 = 0;  // dp[0]
        int prev1 = 0;  // dp[1]
        
        for (int i = 2; i <= n; i++) {
            int oneStep = prev1 + cost[i - 1];
            int twoStep = prev2 + cost[i - 2];
            
            int curr = Math.min(oneStep, twoStep);
            
            // Slide the window forward
            prev2 = prev1;
            // WHY: what was dp[i-1] becomes dp[i-2] in the next iteration
            
            prev1 = curr;
            // WHY: what we just computed becomes dp[i-1] in the next iteration
        }
        
        // prev1 now holds dp[n] — the answer
        return prev1;
    }
}
```

**Time Complexity — O(n):**
Still a single loop from `i = 2` to `i = n`. Same O(n) as tabulation. No change in time complexity.

**Space Complexity — O(1):**
No array of any kind. Just two integer variables — `prev2` and `prev1` — regardless of how large n is. Whether n is 10 or 10 million, memory usage stays constant.

## Final Comparison

| Approach | Time | Space | Notes |
|---|---|---|---|
| Pure Recursion | O(2^n) | O(n) stack | Exponential — never use |
| Memoization | O(n) | O(n) array + O(n) stack | Good interview starting point |
| Tabulation | O(n) | O(n) array | Better — eliminates stack |
| Space Optimization | O(n) | **O(1)** | Best — submit this |

## The Key Takeaway

```
┌──────────────────────────────────────────────────────────────────┐
│  This problem extends Frog Jump with two subtle but important    │
│  shifts — both easy to get backward if you're not careful:       │
│                                                                  │
│  Shift 1 — WHERE the cost is charged:                            │
│  You pay to LEAVE a stair, not to land on one.                   │
│  f(i) = min(f(i-1) + cost[i-1], f(i-2) + cost[i-2])              │
│                          ↑                    ↑                  │
│              cost of the stair you departed FROM, always         │
│                                                                  │
│  Shift 2 — WHERE the destination is:                             │
│  The "top" is index n — one position PAST the last stair —       │
│  not the last stair itself. This extra position is free,         │
│  exactly like the two starting positions are free.               │
│                                                                  │
│  Base case rule for this problem:                                │
│  f(0) = 0 AND f(1) = 0 — BOTH starting points are free,          │
│  because the problem explicitly allows starting from either.     │
│                                                                  │
│  Everything else — the recursion → memoization → tabulation →    │
│  space optimization progression — is the exact same skeleton     │
│  as Frog Jump. Once you spot "jump 1 or jump 2" in a new         │
│  problem, check carefully WHERE the cost is charged and WHERE    │
│  the destination sits — those two details are where variants     │
│  of this same shape differ from each other.                      │
└──────────────────────────────────────────────────────────────────┘
```
