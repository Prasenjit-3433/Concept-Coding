# LC 213. House Robber II

---

# Stage 1: Identification

**Step 1 — Which topic?**

You are given an array of non-negative integers representing houses arranged in a **circle**. You cannot rob two adjacent houses. The catch: the first and last house are now neighbors. Find the maximum money you can rob.

The moment you see **"maximum sum, no adjacent elements"** — you recognize this from House Robber I. But now there is one extra constraint: first and last house are adjacent. The core DP logic stays the same. Only the **problem setup** changes slightly.

**Step 2 — Which pattern?**

Input is still a single array. You are computing a single value that depends on previous values in that array.

That is **Pattern 1: 1D DP (Linear)**.

**Step 3 — Which key concept?**

This is a **variation** of House Robber I — not a new problem. The key insight Striver gives:

```
First and last house cannot BOTH be in the answer
(because they are adjacent in the circular arrangement).

Therefore, the answer must come from one of these two cases:
    Case 1: Consider houses [0 ... n-2]  (leave out the last house)
    Case 2: Consider houses [1 ... n-1]  (leave out the first house)

Answer = max(solve(case 1), solve(case 2))
```

Once you split into two cases, each case is exactly House Robber I — which you already know how to solve.

---

# Stage 2: Intuition Building

### Why does the circular arrangement create a problem?

In House Robber I, the array was linear. First and last had no relationship.

In House Robber II, the array is circular:

```
houses = [2, 3, 2]
indices =  0  1  2
```

House 0 and House 2 are now neighbors. So you **cannot** rob both house 0 and house 2.

If you blindly apply House Robber I logic, it might try to include both house 0 and house 2 (since they are not adjacent in a linear sense). That would give the wrong answer.

### The key observation

Whatever the optimal answer is, it will **never contain both the first and the last house** simultaneously — because they are adjacent.

So the optimal answer must fall into one of exactly two cases:

```
Case 1: The answer does NOT include the last house
        → Safely consider houses [0 ... n-2]
        → Apply House Robber I on this subarray

Case 2: The answer does NOT include the first house
        → Safely consider houses [1 ... n-1]
        → Apply House Robber I on this subarray
```

One of these two cases will contain the true optimal answer. Take the maximum of both.

### Verify with examples

**Example 1:** `nums = [2, 3, 2]`

```
Case 1: houses [0...1] = [2, 3]
        House Robber I on [2, 3] → max(2, 3) = 3

Case 2: houses [1...2] = [3, 2]
        House Robber I on [3, 2] → max(3, 2) = 3

Answer = max(3, 3) = 3 ✓
```

**Example 2:** `nums = [1, 2, 3, 1]`

```
Case 1: houses [0...2] = [1, 2, 3]
        House Robber I on [1, 2, 3]:
            dp[0]=1, dp[1]=max(2,1)=2, dp[2]=max(3+1,2)=4
        Result = 4

Case 2: houses [1...3] = [2, 3, 1]
        House Robber I on [2, 3, 1]:
            dp[0]=2, dp[1]=max(3,2)=3, dp[2]=max(1+2,3)=3
        Result = 3

Answer = max(4, 3) = 4 ✓
```

**Example 3:** `nums = [1, 2, 3]`

```
Case 1: houses [0...1] = [1, 2]
        House Robber I on [1, 2] → max(2, 1) = 2

Case 2: houses [1...2] = [2, 3]
        House Robber I on [2, 3] → max(3, 2) = 3

Answer = max(2, 3) = 3 ✓
```

### Edge case — single house

If `n = 1`, there is only one house. No adjacency issue. Just return `nums[0]`.

# Stage 3: Coding

Since House Robber II reduces to two calls of House Robber I, the first thing to do is extract the House Robber I space-optimized solution as a helper function. Then call it twice.

## Approach — Reduce to Two House Robber I Calls

```java
class Solution {
    public int rob(int[] nums) {
        int n = nums.length;
        
        // Edge case: only one house, no adjacency issue
        if (n == 1) return nums[0];
        
        // Edge case: two houses, pick the larger one
        // (both are adjacent to each other in circular arrangement)
        if (n == 2) return Math.max(nums[0], nums[1]);
        
        // Case 1: Consider houses from index 0 to n-2
        // (leave out the last house entirely)
        // WHY: This ensures first and last are never both included
        int case1 = solve(nums, 0, n - 2);
        
        // Case 2: Consider houses from index 1 to n-1
        // (leave out the first house entirely)
        // WHY: This ensures first and last are never both included
        int case2 = solve(nums, 1, n - 1);
        
        // The true answer must lie in one of these two cases
        return Math.max(case1, case2);
    }
    
    // House Robber I — space optimized solution
    // Runs on the subarray nums[start ... end] inclusive
    private int solve(int[] nums, int start, int end) {
        // prev2 = dp[i-2], initialized as 0 (nothing before start)
        int prev2 = 0;
        
        // prev1 = dp[i-1], initialized as the first element of this range
        int prev1 = nums[start];
        
        for (int i = start + 1; i <= end; i++) {
            // Choice 1: Rob house i
            // prev2 represents best up to i-2 (last non-adjacent house)
            int pick = nums[i] + prev2;
            
            // Choice 2: Skip house i
            // prev1 represents best up to i-1
            int notPick = prev1;
            
            int curr = Math.max(pick, notPick);
            
            // Slide the window forward
            prev2 = prev1;
            // WHY: what was dp[i-1] becomes dp[i-2] in the next iteration
            
            prev1 = curr;
            // WHY: what we just computed becomes dp[i-1] in the next iteration
        }
        
        // prev1 now holds the answer for this subarray range
        return prev1;
    }
}
```

## Complexity Analysis

**Time Complexity — O(n):**
Two calls to the `solve` helper, each running on a subarray of size n-1. Each call does a single loop of n-1 iterations, each doing O(1) work. So total work is 2 × O(n) = O(n). The constant factor of 2 doesn't change the complexity class.

**Space Complexity — O(1):**
The `solve` helper uses only three integer variables — `prev2`, `prev1`, `curr`. No array of any size. No recursion stack. Both calls together use a constant amount of memory regardless of n. That is O(1).

## The Key Takeaway

```
┌──────────────────────────────────────────────────────────────────┐
│  House Robber II teaches a critical problem-solving skill:       │
│                                                                  │
│  When a circular constraint blocks a known solution,             │
│  look for a way to BREAK the circle into linear cases.           │
│                                                                  │
│  The insight here:                                               │
│  First and last can never both be in the answer.                 │
│  → Split into two linear cases.                                  │
│  → Apply the known House Robber I solution to each.              │
│  → Take the maximum.                                             │
│                                                                  │
│  General principle:                                              │
│  When you see a CIRCULAR version of a LINEAR DP problem,         │
│  the solution is almost always:                                  │
│      Run the linear solution TWICE on two overlapping subarrays  │
│      and take the best result.                                   │
│                                                                  │
│  This pattern repeats in other problems too — for example,       │
│  circular arrays in Kadane's (max subarray sum in circular).     │
└──────────────────────────────────────────────────────────────────┘
```
