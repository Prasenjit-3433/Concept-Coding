# LC 494. Target Sum

---

# Stage 1: Identification

**Step 1 — Which topic?**

You are given an array of integers and a target. You need to assign a `+` or `-` sign to each element and count the number of ways the resulting expression equals the target.

The moment you see **"count the number of ways to assign signs"** — that is the signal. To count all ways, you must **try all possible assignments**. And whenever you try all possible ways, **Recursion** is your first thought. And when that recursion has overlapping subproblems — it becomes **Dynamic Programming**.

**Step 2 — Which pattern?**

Each element either gets a `+` sign or a `-` sign — exactly two choices per element, each used exactly once. There is a target constraint. You want to count valid assignments.

That is **Pattern 4: 0/1 Knapsack**.

**Step 3 — Which key concept?**

**Problem Reduction — reduce to Count Partitions with Given Difference.**

This problem does not require any new recurrence, any new state, or any new base case. The key is recognizing that assigning signs is the same as dividing the array into two subsets — a "positive group" and a "negative group" — and counting the ways their difference equals the target.

```
Target Sum (sign assignment)
    ↓ recognize as partition problem
Count Partitions with Given Difference (d = target)
    ↓ reduce mathematically
Count Subsets with Sum K  (K = (totalSum - target) / 2)
```

# Stage 2: Intuition Building

### Why Sign Assignment = Partition Problem

Consider the array `[1, 2, 3, 1]` and target `3`.

One valid assignment: `-1 +2 +3 -1 = 3`

Look at this differently:
- Elements with `+` sign form a subset S1 = `{2, 3}`, sum = 5
- Elements with `-` sign form a subset S2 = `{1, 1}`, sum = 2
- Result: S1 - S2 = 5 - 2 = 3 ✓

Another valid assignment: `+1 -2 +3 +1 = 3`

- S1 = `{1, 3, 1}`, sum = 5
- S2 = `{2}`, sum = 2
- Result: S1 - S2 = 5 - 2 = 3 ✓

**Every sign assignment is equivalent to a partition of the array into two subsets S1 (positive elements) and S2 (negative elements) where S1 - S2 = target.**

This is exactly the **Count Partitions with Given Difference** problem from dp18 — with `d = target`.

### The Mathematical Reduction (carried forward from dp18)

```
S1 + S2 = totalSum    ... (all elements are in one of the two groups)
S1 - S2 = target      ... (given condition)

Adding both:
2 × S1 = totalSum + target
S1 = (totalSum + target) / 2

Subtracting:
2 × S2 = totalSum - target
S2 = (totalSum - target) / 2
```

Finding S2 is sufficient. The question reduces to:

```
Count subsets summing to S2 = (totalSum - target) / 2
```

### Two Elimination Checks

**Check 1 — (totalSum - target) must be non-negative:**

Since all elements are non-negative and subset sums cannot be negative, S2 ≥ 0. This means `totalSum - target ≥ 0`, i.e., `totalSum ≥ target`. If not, return 0.

**Check 2 — (totalSum - target) must be even:**

S2 must be an integer. If `(totalSum - target)` is odd, no valid integer partition exists. Return 0.

### Why Not Solve Directly with +/- Recursion?

You can write a recursion that assigns `+` or `-` at each step. But Striver warns against it:

> "If you go that path, the target might go negative, and you face space complexity issues because you cannot use a dp array indexed by a potentially negative target."

The reduction approach avoids this entirely — the new target `(totalSum - target) / 2` is always non-negative (after the elimination check), so the dp array works cleanly.

### Verifying with the Example

```
arr = [1, 2, 3, 1],  target = 3
totalSum = 7
S2 = (7 - 3) / 2 = 2

Count subsets summing to 2:
{2}   → {arr[1]} ✓
{1,1} → {arr[0], arr[3]} ✓

Answer = 2 ✓
```

# Stage 3: Coding

Since this problem reduces entirely to **Count Partitions with Given Difference** (dp18), the code is a direct call to that solution with `d = target`. We carry forward all four approaches.

## Approach 1 — Memoization (Top-Down DP)

```java
class Solution {
    public int findTargetSumWays(int[] nums, int target) {
        int n = nums.length;

        // Step 1: Compute total sum
        int totalSum = 0;
        for (int num : nums) totalSum += num;

        // Elimination check 1: (totalSum - target) must be non-negative
        // WHY: S2 = (totalSum - target) / 2 must be >= 0
        //      since all elements are non-negative integers
        if (totalSum - target < 0) return 0;

        // Elimination check 2: (totalSum - target) must be even
        // WHY: S2 must be an integer — fractional subsets don't exist
        if ((totalSum - target) % 2 != 0) return 0;

        int k = (totalSum - target) / 2;

        // Delegate to Count Subsets with Sum k
        // WHY k: we derived S2 = (totalSum - target) / 2
        //        counting subsets with sum S2 gives us the answer
        int[][] dp = new int[n][k + 1];
        for (int[] row : dp) Arrays.fill(row, -1);

        return solve(n - 1, k, nums, dp);
    }

    private int solve(int index, int sum, int[] arr, int[][] dp) {
        // Base case: reached index 0
        // WHY handle all sub-cases here (not early sum==0 return):
        //     LeetCode constraints guarantee nums[i] >= 0, so zeros are possible
        //     If arr[0]==0 and sum==0, we have TWO valid ways (pick or not pick)
        //     Early return at sum==0 would count only ONE
        if (index == 0) {
            if (arr[0] == 0 && sum == 0) return 2;  // pick zero OR don't pick zero
            if (sum == 0 || arr[0] == sum) return 1; // exactly one valid way
            return 0;
        }

        // Lookup: already computed?
        if (dp[index][sum] != -1) return dp[index][sum];

        // Choice 1: Not Pick arr[index]
        int notPick = solve(index - 1, sum, arr, dp);

        // Choice 2: Pick arr[index] — only if it doesn't exceed remaining sum
        int pick = 0;
        if (arr[index] <= sum) {
            pick = solve(index - 1, sum - arr[index], arr, dp);
        }

        // ADD because we are counting all valid ways
        dp[index][sum] = notPick + pick;
        return dp[index][sum];
    }
}
```

**Time Complexity — O(n × k):**
Each unique (index, sum) pair is computed exactly once. There are n × (k+1) unique states where k = (totalSum - target) / 2. Each state does O(1) work. Total: O(n × k).

**Space Complexity — O(n × k) + O(n):**
Two sources of space — the dp array of size n × (k+1), and the recursion call stack going n levels deep. Total: O(n × k) + O(n).

## Approach 2 — Tabulation (Bottom-Up DP)

```java
class Solution {
    public int findTargetSumWays(int[] nums, int target) {
        int n = nums.length;

        int totalSum = 0;
        for (int num : nums) totalSum += num;

        if (totalSum - target < 0) return 0;
        if ((totalSum - target) % 2 != 0) return 0;

        int k = (totalSum - target) / 2;

        // dp[i][s] = number of subsets in nums[0..i] summing to exactly s
        int[][] dp = new int[n][k + 1];

        // Base case: index = 0
        // WHY separate zero check: if nums[0]==0, both "pick" and "not pick"
        //     give sum 0 → two valid subsets for sum=0 instead of one
        if (nums[0] == 0) {
            dp[0][0] = 2;   // pick zero OR don't pick zero
        } else {
            dp[0][0] = 1;   // don't pick nums[0] → sum 0 in 1 way
            if (nums[0] <= k) {
                dp[0][nums[0]] = 1; // pick nums[0] → sum nums[0] in 1 way
            }
        }

        // Fill from index=1 to n-1
        for (int i = 1; i < n; i++) {
            for (int s = 0; s <= k; s++) {

                // Choice 1: Not Pick nums[i]
                // WHY dp[i-1][s]: skip nums[i], look at previous row same sum
                int notPick = dp[i - 1][s];

                // Choice 2: Pick nums[i] — only if it fits within s
                // WHY dp[i-1][s - nums[i]]: used nums[i], remaining sum
                //     shrinks, check previous row for that reduced sum
                int pick = 0;
                if (nums[i] <= s) {
                    pick = dp[i - 1][s - nums[i]];
                }

                dp[i][s] = notPick + pick;
            }
        }

        return dp[n - 1][k];
    }
}
```

**Time Complexity — O(n × k):**
Two nested loops — outer runs n-1 times, inner runs k+1 times. Each cell does O(1) work. Total: O(n × k).

**Space Complexity — O(n × k):**
Only the dp array of size n × (k+1). No recursion stack at all.

## Approach 3 — Space Optimization (The Final Form)

```
dp[i][s] = dp[i-1][s] + dp[i-1][s - nums[i]]
```

Row `i` only depends on row `i-1`. Replace the full 2D table with two 1D arrays of size k+1.

```java
class Solution {
    public int findTargetSumWays(int[] nums, int target) {
        int n = nums.length;

        int totalSum = 0;
        for (int num : nums) totalSum += num;

        if (totalSum - target < 0) return 0;
        if ((totalSum - target) % 2 != 0) return 0;

        int k = (totalSum - target) / 2;

        // prev[s] = number of subsets in elements seen so far summing to s
        // Initialize with base case for index=0
        int[] prev = new int[k + 1];

        // Base case: index=0
        if (nums[0] == 0) {
            prev[0] = 2;   // pick zero OR don't pick zero — two valid subsets
        } else {
            prev[0] = 1;   // don't pick nums[0] → sum 0 in 1 way
            if (nums[0] <= k) {
                prev[nums[0]] = 1; // pick nums[0] → one valid subset
            }
        }

        // Fill from index=1 to n-1
        for (int i = 1; i < n; i++) {
            // curr[s] = number of subsets in nums[0..i] summing to s
            int[] curr = new int[k + 1];

            for (int s = 0; s <= k; s++) {
                // Not Pick nums[i]
                // WHY prev[s]: skip nums[i], answer lives in previous row
                int notPick = prev[s];

                // Pick nums[i] — only if it fits within s
                // WHY prev[s - nums[i]]: used nums[i], check previous row
                //     for whether remaining sum was achievable
                int pick = 0;
                if (nums[i] <= s) {
                    pick = prev[s - nums[i]];
                }

                curr[s] = notPick + pick;
            }

            // Slide forward: current row becomes new previous row
            // WHY: next iteration needs this row as its "row above"
            prev = curr;
        }

        // prev now holds answers for the full array
        return prev[k];
    }
}
```

**Time Complexity — O(n × k):**
Two nested loops with the same iteration count as tabulation. Total: O(n × k). No change.

**Space Complexity — O(k):**
No n × (k+1) array. No recursion stack. Just two arrays of size k+1 — `prev` and `curr`. Memory depends only on k = (totalSum - target) / 2.

## Final Comparison

| Approach | Time | Space | Notes |
|---|---|---|---|
| Memoization | O(n × k) | O(n×k) + O(n) stack | Good interview starting point |
| Tabulation | O(n × k) | O(n × k) | Better — eliminates stack |
| Space Optimization | O(n × k) | **O(k)** | Best — submit this |

where k = (totalSum - target) / 2

## The Reduction Chain in Pattern 4 So Far

```
Subset Sum Equal to Target          → existence:  return true/false, use OR
    ↓ change OR to ADD
Count Subsets with Sum K            → counting:   return 1/0, use ADD
    ↓ change target mathematically (S2 = (totalSum - d) / 2)
Count Partitions with Given Diff    → counting with derived target
    ↓ recognize sign assignment as partition
Target Sum (LC 494)                 → same problem, different language
```
