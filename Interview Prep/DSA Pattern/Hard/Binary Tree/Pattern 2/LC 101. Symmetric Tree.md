# LC 101. Symmetric Tree

---

# Stage 1: Identification

**Step 1 — Which topic?**

You are given the root of a binary tree. You need to determine whether it is **symmetric around its center** — that is, whether the left half of the tree is a **mirror image** of the right half.

**Step 2 — Which pattern?**

Still **Pattern 2: Tree Properties** — you are computing a structural fact about the whole tree. The trigger:

> "symmetric", "mirror of itself" → **Tree Properties**

**Step 3 — Which key concept?**

**Mirror check — compare left and right subtrees simultaneously, using a function that takes TWO nodes instead of one.**

This is a genuinely new structural shape compared to every problem so far in this pattern. LC 104, LC 110, and LC 543 all used a recursive function that took **one node** and returned information about it. This problem needs a function that takes **two nodes at once** and checks whether they are mirror images of each other — because "symmetric" is fundamentally a relationship *between* the left subtree and the right subtree, not a property of a single node in isolation.

---

# Stage 2: Intuition Building

### What Does "Symmetric" Actually Mean?

Picture drawing a vertical line straight down through the root of the tree — that line is the "mirror." A tree is symmetric if folding the tree along that line makes the left half land exactly on top of the right half.

**Example 1 — Symmetric:**

```
1 2
1 2
2 3
2 4
```

Wait — let's use the actual node values from Striver's example directly:

```
        1
       / \
      2   2
     / \ / \
    3  4 4  3
```

Edge-list notation:
```
1 2
1 2
2 3
2 4
2 4
2 3
```
(first `2` is the left child of `1`, second `2` is the right child of `1`; first `2`'s children are `3` then `4`; second `2`'s children are `4` then `3`)

Fold this tree down the middle: the left `2` lands on the right `2` ✓. The left `2`'s children are `3, 4` (left to right); the right `2`'s children are `4, 3` (left to right) — which, when *mirrored*, reads `3, 4` — matching. **Symmetric.**

**Example 2 — Not Symmetric:**

```
        1
       / \
      2   2
       \   \
        3   3
```

Both `2`s have a right child of `3`, and no left child. Fold the tree: the left `2`'s child (`3`, hanging to its *right*) should land on the right `2`'s child (`3`, hanging to its *right*) — but a true mirror image requires that if the left `2`'s child hangs right, the right `2`'s child should hang **left** (mirrored direction). Since both hang the *same* direction, this is **not symmetric**, even though the values line up.

```
┌────────────────────────────────────────────────────────────────┐
│  Symmetry is NOT just "do the same values appear on both       │
│  sides." It's about DIRECTION too — a true mirror flips        │
│  left and right, not just copies them straight across.         │
└────────────────────────────────────────────────────────────────┘
```

---

### The Core Insight — What a Mirror Actually Does

Stand at an actual mirror. What's true about your reflection?

> *Your left hand appears where your reflection's right hand is. Your right hand appears where your reflection's left hand is.*

That's the entire definition of a mirror: **left and right get swapped.**

Now apply that to the tree. Ignore the root itself for a moment — think of the tree as splitting into two halves at the root: a **left subtree** (rooted at `root.left`) and a **right subtree** (rooted at `root.right`). For the whole tree to be symmetric, these two subtrees must be **mirror images of each other**.

### Translating "Mirror" Into a Traversal Rule

Suppose you do an **inorder-style** traversal on the left subtree: **root, then left, then right.**

For the *mirrored* version of that same traversal to visit corresponding nodes on the right subtree, it must do the *opposite* at every step: **root, then RIGHT, then LEFT.**

```
┌────────────────────────────────────────────────────────────────┐
│  Left subtree traversal:   root → LEFT  → RIGHT                │
│  Right subtree traversal:  root → RIGHT → LEFT   (mirrored)    │
│                                                                │
│  If you walk BOTH subtrees simultaneously, one going           │
│  left-then-right and the other going right-then-left,          │
│  and every corresponding pair of nodes you visit has the       │
│  SAME value (and the same null/non-null pattern) —             │
│  the tree is symmetric.                                        │
└────────────────────────────────────────────────────────────────┘
```

This is the entire algorithm. Nothing more sophisticated needs to be invented.

---

### Why the Recursive Function Needs TWO Node Parameters

Every previous problem in this pattern — height, balance, diameter — asked "what is true about *this one node* and what it returns from its children?" That's a **single-node** recursion.

This problem asks a *relational* question: "are *these two* nodes (and everything below them) mirror images of each other?" That is fundamentally a **two-node** recursion — you cannot answer it by looking at one node at a time. So the function signature itself must change shape:

```
single-node pattern (LC 104, 110, 543):   solve(node)        → returns info about ONE subtree
this problem's pattern:                    solve(nodeA, nodeB) → returns whether TWO subtrees mirror each other
```

### Walking Through the Simultaneous Movement

Call the two starting points `left = root.left` and `right = root.right`. At every step, you're standing at one node from each side, and you check three things, in order:

```
1. Are BOTH null?
   → Two empty subtrees are trivially mirror images of each
     other (nothing to compare). This is the base case — return true.

2. Is EXACTLY ONE of them null (the other isn't)?
   → A mirror image cannot have "something" on one side and
     "nothing" on the other at corresponding positions.
     Immediately return false.

3. Are both non-null, but their VALUES differ?
   → The mirror positions don't hold matching values.
     Immediately return false.

4. Otherwise (both non-null, values match):
   → Recurse into the MIRRORED pair of children:
       left.left  paired with  right.right   (outer edges)
       left.right paired with  right.left    (inner edges)
   → Both of these recursive checks must return true for
     this pair to be considered a match.
```

The mirrored pairing in step 4 is the heart of the whole technique — `left.left` must mirror `right.right` (both are the "outermost" children relative to the center line), and `left.right` must mirror `right.left` (both are the "innermost" children). Get this pairing backwards and the algorithm silently checks for plain equality instead of mirror symmetry.

### Walking Through Striver's Symmetric Example

```
        1
       / \
      2   2
     / \ / \
    3  4 4  3
```

Start: `left = root.left` (the first `2`), `right = root.right` (the second `2`).

```
Compare (2, 2): both non-null, values match ✓
  → recurse (left.left, right.right)  = (3, 3)
  → recurse (left.right, right.left)  = (4, 4)

Compare (3, 3): both non-null, values match ✓
  → recurse (null, null) → both null → true
  → recurse (null, null) → both null → true
  → this pair returns TRUE

Compare (4, 4): both non-null, values match ✓
  → recurse (null, null) → true
  → recurse (null, null) → true
  → this pair returns TRUE

Back at (2, 2): both recursive branches returned TRUE
  → this pair returns TRUE

Final result: TRUE → the tree is symmetric ✓
```

### Walking Through Striver's Non-Symmetric Example

```
        1
       / \
      2   2
       \   \
        3   3
```

```
Compare (2, 2): both non-null, values match ✓
  → recurse (left.left, right.right) = (null, 3)
  → recurse (left.right, right.left) = (3, null)

Compare (null, 3): ONE is null, the other isn't
  → immediately return FALSE

Back at (2, 2): one branch already returned FALSE
  → this pair returns FALSE

Final result: FALSE → the tree is NOT symmetric
```

Notice exactly *why* it fails: `left.left` is `null` (the left `2` has no left child), but its mirror partner `right.right` is `3` (the right `2` *does* have a right child). A true mirror would require the right `2` to have its child hanging on the **left** instead — but it doesn't. The direction mismatch is caught immediately.

---

### Why the Recursion Terminates

Every recursive call moves both pointers one level deeper into their respective subtrees. Since the tree is finite with no cycles, both pointers eventually hit `null` along every path. The base case (`both null → true`) or the early-exit case (`one null, one not → false`) catches this and returns — unwinding the recursion.

### Why This Is Still O(n) — Not a New Complexity Class

Even though the function now takes two arguments, each recursive call still corresponds to visiting one new pair of nodes, and every node in the tree is visited **at most once** across the whole process (once as a "left-side" node, once as a "right-side" node, but never revisited). So the total work remains bounded by the number of nodes: **O(n)**.

# Stage 3: Coding

## Approach — Recursive, Two-Node Simultaneous Traversal

**Mental workflow before writing a single line:**

```
1. Edge case: if root is null → trivially symmetric → return true

2. Call solve(root.left, root.right)

3. Inside solve(nodeA, nodeB):
   → if both null: return true       (base case — nothing to compare)
   → if exactly one is null: return false   (structural mismatch)
   → if nodeA.val != nodeB.val: return false   (value mismatch)
   → otherwise, recurse on the MIRRORED pairs:
       outer pair: solve(nodeA.left, nodeB.right)
       inner pair: solve(nodeA.right, nodeB.left)
   → return true only if BOTH recursive calls return true
```

```java
class Solution {
    public boolean isSymmetric(TreeNode root) {
        // An empty tree (or a tree with just a root and no
        // children at all) is trivially symmetric — there's
        // nothing on either side to conflict.
        if (root == null) return true;

        // The tree is symmetric iff its LEFT subtree and
        // RIGHT subtree are mirror images of each other.
        return solve(root.left, root.right);
    }

    // Checks whether nodeA and nodeB (and everything below them)
    // form a mirror-image pair.
    private boolean solve(TreeNode nodeA, TreeNode nodeB) {

        // Base case: both sides ran out at the same time —
        // two empty subtrees are trivially mirror images
        if (nodeA == null && nodeB == null) return true;

        // Structural mismatch: one side has a node here,
        // the other doesn't. A mirror cannot have "something"
        // facing "nothing" at corresponding positions.
        if (nodeA == null || nodeB == null) return false;

        // Value mismatch: both nodes exist, but don't hold
        // the same value — can't be mirror images
        if (nodeA.val != nodeB.val) return false;

        // Recurse into the MIRRORED pairing:
        // nodeA's LEFT must mirror nodeB's RIGHT (outer edges)
        // nodeA's RIGHT must mirror nodeB's LEFT (inner edges)
        boolean outerMatch = solve(nodeA.left, nodeB.right);
        boolean innerMatch = solve(nodeA.right, nodeB.left);

        // Both mirrored pairs must hold for THIS pair to be
        // considered a valid mirror match
        return outerMatch && innerMatch;
    }
}
```

## Complexity Analysis

**Time Complexity — O(n):**

Every node in the tree participates in exactly one `solve()` call across the entire process — either as the `nodeA` argument or the `nodeB` argument at some point in the recursion tree. Each call does a constant amount of work (a couple of null checks, a value comparison), so with `n` total nodes, total work is **O(n)**.

**Space Complexity — O(h), where h is the height of the tree:**

The only auxiliary space is the recursion call stack. Because two subtrees are being walked **simultaneously** (in lockstep, one level at a time on both sides together), the maximum call stack depth at any point is still bounded by the height of the tree — not double it — since both branches of any given call finish before the next level's calls stack up further.

- **Best case (balanced tree):** `h = O(log n)`.
- **Worst case (skewed tree):** `h = O(n)`, exactly the same worst-case reasoning as every other recursive traversal in this pattern.

So: **O(h) auxiliary space — O(log n) balanced, O(n) worst case (skewed tree)**.
