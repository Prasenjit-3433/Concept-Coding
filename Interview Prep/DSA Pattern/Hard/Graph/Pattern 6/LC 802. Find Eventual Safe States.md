# LC 802. Find Eventual Safe States

---

# Stage 1: Identification

**Step 1 — Which topic?**

You are given a directed graph. You need to find nodes from which every possible path leads to a terminal node. This is a **graph traversal + structural reasoning** problem → **Graph**.

**Step 2 — Which pattern?**

Let's think about what makes a node "unsafe":
- If a node is part of a cycle → it can never lead to a terminal node → unsafe
- If a node leads into a cycle → unsafe
- If all paths from a node eventually terminate → safe

So the question reduces to: **which nodes are NOT part of or leading into a cycle?**

Now the key insight Striver gives:
> *"I know for sure that terminal nodes are safe. Can I work backwards from terminal nodes to find all safe nodes?"*

Working backwards from terminal nodes — that is **reverse graph + Kahn's Algorithm (Topological Sort)**

The trigger:
> "safe nodes", "all paths lead to terminal", "find nodes not in cycles" → **Topological Sort on Reversed Graph**

**Step 3 — Which key concept?**

**Reverse Graph + Kahn's Algorithm**

Why reverse the graph?
- In the original graph, terminal nodes have **out-degree 0**
- After reversing, terminal nodes have **in-degree 0**
- Kahn's algorithm starts from in-degree 0 nodes and propagates
- So reversing lets Kahn's naturally start from terminal nodes and work backwards

This is the key insight that makes topological sort applicable here.

# Stage 2: Intuition Building

### The Core Question

Ask yourself first:

> *"Which nodes am I 100% sure are safe?"*

**Terminal nodes** — nodes with no outgoing edges. Every path starting from them trivially ends at a terminal node (themselves).

> *"Which nodes become safe because of terminal nodes?"*

Any node whose **all** outgoing edges lead to safe nodes — it is also safe.

> *"Which nodes can never be safe?"*

Nodes that are part of a cycle — they loop forever and never reach a terminal node.

This is a **backwards propagation** problem. Start from what you know (terminal nodes = safe), propagate backwards through the graph, mark more nodes safe as you go.

---

### Why Reverse the Graph?

In the **original graph**:
- Terminal nodes have out-degree 0
- Kahn's algorithm works with **in-degree 0** nodes
- There is no natural way to start Kahn's from terminal nodes in the original graph

After **reversing all edges**:
- Terminal nodes now have **in-degree 0** (nothing points to them in the reversed graph)
- Kahn's algorithm naturally picks them up first
- When we process a terminal node and reduce its neighbors' in-degrees, we are saying: *"one path leading to safety has been confirmed"*
- When a node's in-degree reaches 0 in the reversed graph, it means **all** its original outgoing edges led to safe nodes → it is safe too

```
Original graph:          Reversed graph:
A → B → C (terminal)     C → B → A
         ↑                         
         D (terminal)    D → B    
```

In reversed graph, C and D have in-degree 0 → Kahn's picks them first → reduces B's in-degree → when B reaches 0 → B is safe → reduces A's in-degree → A is safe.

### The Key Insight to Carry

```
┌────────────────────────────────────────────────────────────────┐
│  Safe node = not part of or leading into a cycle               │
│                                                                │
│  Strategy: work BACKWARDS from terminal nodes                  │
│                                                                │
│  Reverse the graph → terminal nodes get in-degree 0            │
│  → Kahn's BFS naturally starts from them                       │
│  → Every node that gets fully processed = safe node            │
│  → Nodes that never reach in-degree 0 = in a cycle = unsafe    │
│                                                                │
│  Final step: sort the safe nodes before returning              │
└────────────────────────────────────────────────────────────────┘
```

# Stage 3: Coding

### Brute Force

> "For every node, do a DFS and check if all paths from it lead to terminal nodes."

- For each node: run DFS, track all reachable paths
- If any path loops forever (cycle) → node is unsafe
- O(V × (V + E)) — check every node separately

Impractical for large graphs. Establishes the baseline only.

---

### Better — DFS with 3-Color Cycle Detection

This is what Striver solved in the earlier cycle detection video. For each node:
- WHITE = unvisited
- GRAY = currently in DFS path
- BLACK = confirmed safe

If DFS from a node reaches a GRAY node → cycle → unsafe.
If DFS completes without hitting GRAY → safe.

Works correctly but we are solving it with topological sort here to practice that pattern.

---

### Optimal — Reverse Graph + Kahn's Algorithm

```java
class Solution {
    public List<Integer> eventualSafeNodes(int[][] graph) {
        int V = graph.length;

        // Step 1: Build the REVERSED adjacency list
        // Original edge i → j becomes reversed edge j → i
        List<List<Integer>> adjRev = new ArrayList<>();
        for (int i = 0; i < V; i++) {
            adjRev.add(new ArrayList<>());
        }

        // Also compute in-degree in the REVERSED graph
        int[] inDegree = new int[V];

        for (int i = 0; i < V; i++) {
            for (int neighbor : graph[i]) {
                // Original: i → neighbor
                // Reversed: neighbor → i
                adjRev.get(neighbor).add(i);
                inDegree[i]++;
                // WHY inDegree[i]++?
                // In the reversed graph, edge goes neighbor → i
                // So i gets one more incoming edge
            }
        }

        // Step 2: Seed queue with in-degree 0 nodes
        // These are terminal nodes in the original graph
        // (out-degree 0 in original = in-degree 0 in reversed)
        Queue<Integer> queue = new LinkedList<>();
        for (int i = 0; i < V; i++) {
            if (inDegree[i] == 0) {
                queue.add(i);
            }
        }

        // Step 3: Kahn's BFS on reversed graph
        List<Integer> safeNodes = new ArrayList<>();

        while (!queue.isEmpty()) {
            int node = queue.poll();
            safeNodes.add(node);
            // This node is confirmed safe:
            // either it's a terminal node, or all its
            // original outgoing paths led to safe nodes

            for (int neighbor : adjRev.get(node)) {
                inDegree[neighbor]--;
                // WHY: in the reversed graph, this edge is
                // neighbor → node. We've confirmed node is safe,
                // so one of neighbor's original outgoing edges
                // is confirmed to lead to safety.

                if (inDegree[neighbor] == 0) {
                    queue.add(neighbor);
                    // WHY: ALL of neighbor's original outgoing
                    // edges now lead to safe nodes.
                    // So neighbor itself is safe.
                }
            }
        }

        // Step 4: Sort before returning
        // (problem requires ascending order)
        Collections.sort(safeNodes);
        return safeNodes;
    }
}
```

## Complexity Analysis

| | Complexity | Reason |
|---|---|---|
| **Time** | O(V + E + V log V) | O(V+E) for building reversed graph + Kahn's BFS. O(V log V) for final sort. |
| **Space** | O(V + E) | Reversed adjacency list O(V+E), in-degree array O(V), queue O(V). |

The extra overhead vs plain Kahn's: the reversed graph storage O(V+E) and the sort O(V log V). Striver explicitly calls this out in the lecture.
