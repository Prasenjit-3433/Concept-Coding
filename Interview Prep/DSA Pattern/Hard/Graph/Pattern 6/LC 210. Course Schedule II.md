# LC 210. Course Schedule II

---

## Stage 1: Identification

**Step 1 — Which topic?**

You are given courses with prerequisites — "to take course 0, you must first finish course 1." This is a **dependency/ordering** problem. The moment you see *"X must be done before Y"*, the topic is **Graph**.

**Step 2 — Which pattern?**

The problem asks for the **actual ordering** in which all courses can be taken. A valid ordering exists only if there are no circular dependencies. Finding a linear ordering where all dependencies come before dependents is the exact definition of **Topological Sort** (Pattern 6).

The trigger is direct:
> "prerequisites", "finish all courses", "return the ordering" → **Topological Sort**

**Step 3 — Which key concept?**

**Kahn's Algorithm — BFS with In-degree**

Why Kahn's over DFS here?
- DFS gives yes/no for cycle detection cleanly
- But for the **actual ordering**, Kahn's is more natural — nodes come out of the queue already in valid topological order, no reversal needed
- This is exactly what Striver emphasizes in the lecture

---

## Stage 2: Intuition Building

### The Core Question

Before thinking about any algorithm, ask yourself:

> *"Which course can I safely take first — without violating any prerequisite?"*

Answer: **Any course that has zero prerequisites.** No course needs to be done before it. It is free to take immediately.

This is the in-degree = 0 idea. A course with in-degree 0 has no incoming edges — nothing needs to precede it.

---

### Understanding the Input — Edge Direction is Critical

In LC 210, a pair `[0, 1]` means:
> *"To take course 0, you must first finish course 1."*

So the **edge goes: 1 → 0** (course 1 must come before course 0)

```
pair [a, b]  →  edge direction: b → a
```

This is the **opposite** of how you might first read it. Get this wrong and the entire graph is reversed.

---

### Concrete Example — Valid Ordering Exists

```
numCourses = 4
prerequisites = [[1,0],[2,0],[3,1],[3,2]]
```

Reading each pair `[a, b]` as edge `b → a`:
```
[1,0] → edge 0 → 1
[2,0] → edge 0 → 2
[3,1] → edge 1 → 3
[3,2] → edge 2 → 3
```

Paste into csacademy.com:
```
0 1
0 2
1 3
2 3
```

In-degrees:
```
Course 0 → in-degree 0  (no prerequisites, free to take)
Course 1 → in-degree 1  (needs 0)
Course 2 → in-degree 1  (needs 0)
Course 3 → in-degree 2  (needs both 1 and 2)
```

Processing step by step:

```
Queue starts with: [0]   ← only course with in-degree 0

Step 1: Pop 0 → order = [0]
        Neighbor 1: in-degree 1→0 → push 1
        Neighbor 2: in-degree 1→0 → push 2
        Queue: [1, 2]

Step 2: Pop 1 → order = [0, 1]
        Neighbor 3: in-degree 2→1 (not zero yet, don't push)
        Queue: [2]

Step 3: Pop 2 → order = [0, 1, 2]
        Neighbor 3: in-degree 1→0 → push 3
        Queue: [3]

Step 4: Pop 3 → order = [0, 1, 2, 3]
        No neighbors.
        Queue: []
```

Processed count = 4 = numCourses → **No cycle → Valid ordering: [0, 1, 2, 3]**

### Concrete Example — Cycle Exists, No Valid Ordering

```
numCourses = 3
prerequisites = [[0,1],[1,2],[2,0]]
```

Edges `b → a`:
```
[0,1] → 1 → 0
[1,2] → 2 → 1
[2,0] → 0 → 2
```

Paste into csacademy.com:
```
1 0
2 1
0 2
```

In-degrees:
```
Course 0 → in-degree 1  (needs 1)
Course 1 → in-degree 1  (needs 2)
Course 2 → in-degree 1  (needs 0)
```

Nobody has in-degree 0. Queue starts **empty**.

```
Queue: []  →  nothing to process
Processed count = 0 ≠ 3
```

**Cycle detected → return empty array []**

The nodes inside the cycle can never reach in-degree 0 — they are all waiting on each other. They never enter the queue. This is cycle detection for free.

### The Key Insight to Carry

```
┌────────────────────────────────────────────────────────────┐
│  "Return the ordering to finish all courses"               │
│       = "Find topological order of the dependency graph"   │
│                                                            │
│  Kahn's BFS naturally produces the ordering as it runs.    │
│  No reversal needed — nodes exit the queue in valid order. │
│                                                            │
│  If processed count == n  →  return the order array        │
│  If processed count < n   →  cycle → return []             │
└────────────────────────────────────────────────────────────┘
```

## Stage 3: Coding

### Brute Force

> "Try every permutation of n courses. For each permutation, check if every prerequisite pair is satisfied."

- Generate all n! orderings
- For each ordering, verify all prerequisite constraints → O(n! × m)
- Return the first valid one, or [] if none found

Completely impractical — n can be up to 2000. Exists only to establish baseline. No code needed.

---

### Optimal — Kahn's Algorithm

**Mental workflow before writing a single line:**

```
1. Build adjacency list
   → for each pair [a, b]: add edge b → a
      (b must be taken before a)

2. Compute in-degree for every course
   → in-degree[course] = number of prerequisites it has

3. Seed queue with all courses having in-degree 0
   → these are the courses with no prerequisites

4. BFS:
   → pop a course, add it to result order
   → for each neighbor: reduce in-degree by 1
   → if neighbor's in-degree becomes 0, push to queue

5. After BFS:
   → if result.size() == n: return result
   → else: cycle exists, return []
```

```java
class Solution {
    public int[] findOrder(int numCourses, int[][] prerequisites) {

        // Step 1: Build adjacency list
        // pair [a, b] means: to take a, must finish b first
        // so directed edge goes: b → a
        List<List<Integer>> adj = new ArrayList<>();
        for (int i = 0; i < numCourses; i++) {
            adj.add(new ArrayList<>());
        }
        for (int[] pre : prerequisites) {
            adj.get(pre[1]).add(pre[0]);
            // pre[1] must come before pre[0]
            // so edge: pre[1] → pre[0]
        }

        // Step 2: Compute in-degree for every course
        int[] inDegree = new int[numCourses];
        for (int i = 0; i < numCourses; i++) {
            for (int neighbor : adj.get(i)) {
                inDegree[neighbor]++;
            }
        }
        // WHY: in-degree = number of courses that must be
        // completed before this one. Only when all of them
        // are done (in-degree drops to 0) can we take it.

        // Step 3: Seed queue with zero in-degree courses
        Queue<Integer> queue = new LinkedList<>();
        for (int i = 0; i < numCourses; i++) {
            if (inDegree[i] == 0) {
                queue.add(i);
            }
        }
        // WHY: these courses have no prerequisites at all.
        // They are safe to take immediately.

        // Step 4: BFS — build the ordering
        int[] order = new int[numCourses];
        int idx = 0;

        while (!queue.isEmpty()) {
            int course = queue.poll();
            order[idx++] = course;
            // This course is now completed.
            // Its contribution to neighbors' prerequisites
            // is now removed.

            for (int neighbor : adj.get(course)) {
                inDegree[neighbor]--;
                // WHY: course is done, so one prerequisite
                // of neighbor is satisfied.

                if (inDegree[neighbor] == 0) {
                    queue.add(neighbor);
                    // WHY: all prerequisites of neighbor
                    // are now satisfied. Safe to take it.
                }
            }
        }

        // Step 5: Return result
        // If all courses processed → valid ordering found
        // If not → cycle exists → impossible
        if (idx == numCourses) return order;
        return new int[]{};
    }
}
```

```
numCourses = 4
```

After building graph (edge b → a):

In-degree array:
```
inDegree = [0, 1, 1, 2]
```

```
Queue: [0]
order = []

--- Iteration 1 ---
Pop 0 → order = [0], idx = 1
  neighbor 1: inDegree[1] = 1→0 → push 1
  neighbor 2: inDegree[2] = 1→0 → push 2
Queue: [1, 2]

--- Iteration 2 ---
Pop 1 → order = [0,1], idx = 2
  neighbor 3: inDegree[3] = 2→1 (not 0, don't push)
Queue: [2]

--- Iteration 3 ---
Pop 2 → order = [0,1,2], idx = 3
  neighbor 3: inDegree[3] = 1→0 → push 3
Queue: [3]

--- Iteration 4 ---
Pop 3 → order = [0,1,2,3], idx = 4
  no neighbors
Queue: []

idx = 4 == numCourses = 4
return [0, 1, 2, 3]
```

## Complexity Analysis

| | Complexity | Reason |
|---|---|---|
| **Time** | O(V + E) | Every course enqueued/dequeued once (V). Every prerequisite edge processed once (E). |
| **Space** | O(V + E) | Adjacency list O(V+E), in-degree array O(V), queue O(V), result O(V). |
